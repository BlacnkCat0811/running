## 视觉与交互规范

- 背景 #090E17；卡片 #141E2D；主色 #69E4F2；辅助色 #8896FF；警告采用珊瑚色。
- 中文字体采用苹方，英文及数字采用 SF Pro；数据用等宽数字，正文不使用像素字体。
- 采用连续圆角卡片、细边线、柔和局部光感和清晰留白；图表始终保留单位、图例和数值，不靠颜色单独传达信息。
- 保留今日、训练、统计、趋势、设置五个主导航入口，计划从今日进入。次级页面显示返回标题。
- 建议正文至少 15pt、次级文案 12pt，主要触控区域至少 44pt；原图为概念视觉，开发时应校验动态字号和实际安全区域。
- 加载时用骨架或进度反馈；空数据不填零分；离线明确缓存时间；计划保存冲突提示重载，不能显示已保存。
- 健康同步仅只读，保留权限管理入口。图中阶段和百分比为示意，实际应按已有同步状态展示，不能虚构后台能力或精确进度。
- 数据与评分继续来自现有服务。图片中新增的装饰性曲线、趋势带不构成新计算接口要求。

## 视觉验收备注

生成图用于确认视觉方向与信息层级，局部小字可能失真，示例日期也不作为最终文案。实际实现以现有产品数据和下列约束为准：

- 首页图中若出现“开始训练”，应采用现有“锁定今日安排”操作，不新增跑步录制能力。
- 计划编辑仍属于从今日进入的次级流程，不因生成图中选中图标的变化而切换主导航。
- 训练配速分区使用 E/M/T/I/R，心率分区使用 Z1–Z5，两者不可混写；图中说明文字需在设计落地时校对。
- 图中准备度、恢复度等示例数字不新增计算逻辑；展示仅限现有接口可提供的字段。

### 生成方式

使用 imagegen 技能的标准 CLI，模型 `gpt-image-2`，通过用户指定的 API 服务生成。目标尺寸 3840 × 2160，high 质量。完整提示词见 `prompts.jsonl`。密钥不写入设计文件。

| 路径 | 克隆体积 | 代价 | 结论 |
| --- | --- | --- | --- |
| `git rm --cached` | **不变**（历史里 27 MB 仍在） | 几乎为零 | 只清理当前提交，治标 |
| 迁 Git LFS | 减小 | 需重写历史 + 引入 LFS 服务端依赖；本仓单人维护、远端 gitee，协作收益为零 | 未采用 |
