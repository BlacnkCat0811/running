## 2. 仅离线可用的候选核心

- [共享合同](../packages/api-contracts/src/coach-loop.ts)：证据/原因/manifest、剂量、历史锚点、S/H、约束和候选结果。
- [容量](../apps/api/src/weekly-capacity.ts)：最近四个完整自然周的B、上个完整周P、28日/8日期资格；候选H=min(B×1.30,P×1.30)，本周训练不抬自己的锚点，支持显式证据修订。
- [追加资格](../apps/api/src/coach-extension-eligibility.ts)：生命周期、同日训练/预留、可用时长、分区、同步、负荷/恢复flags、赛前、训练前56日单次参考、最近7日单次异常、滚动7日次数及硬窗口逐项解释。
- [候选出口](../apps/api/src/coach-loop-decision.ts)：S只规划常规部分，H约束自然周和所有受影响滚动7/14日窗口；纳入窗口外预留，同槽位去重，实际替换预留；S20、实际20、H26时可评估30分钟/5km追加且S不变。
- [执行评价](../apps/api/src/coach-execution-assessment.ts)：观测/剂量/刺激分别输出；候选90%剂量、80%有效覆盖/目标时间边界。重建组不能自证完成，汇总/平均值不能证明目标时间，实测组需逐组满足且恢复边界可辨；明确关联、多训练、迟到、撤回、事后处方与重复抵扣分别处理。间歇仅心率而未有可靠滞后政策时不确认。兼容观测数与确认/已知未满足/未知分母分开。
- [最小修补](../apps/api/src/coach-plan-repair.ts)：最多七日、每日期五个候选，约束闭包限窗口内，窗口外作为固定输入交给既有校验；按日期/移动/课型/可比工作剂量/偏好字典序选取。记录最终校验后的变化，保护存储不妨碍有效安全限制；授权状态也是执行身份。搜索预算耗尽不发布部分最优解。
- [反馈](../apps/api/src/coach-subjective-feedback.ts)：候选规范化、上海午夜有效期、可得时间/数据域/修订与墓碑选择。全跳过返回null，不填正常；RPE仅关联已存在的override修订，不接受第二份值；训练后原因不成为次日训练前状态。没有新增采集接口、数据库表或Fitness输入。
- [目标差距](../apps/api/src/coach-goal-gap.ts)：只读候选装配，绑定bundle/事实/override/标签/模型/域/情景，数据截止超过七个本地日为陈旧；差值为参考秒数减目标秒数。未校准、个人参考与经验评价不互相改名，不输出概率，缺摘要不调用报告构建器。
- 剂量/追加候选固定`executable=false`、`authorizedDecisionRef=null`；新评价/修补/反馈/差距明确`policyStatus=candidate`。没有HTTP启用开关、生产资格收据、策略签字或个人“已知安全”声明。O2/O3/O5/O6的新容差、联合规则与摘要新鲜度仍需相应评审。

**生产仍使用旧限制语义。** S零头不足或已完成且无完整常规课空间时，当前接口会休息并明确追加尚未启用；“20km后真实发布并执行追加课”的AC0-13仍未通过。关闭旧上限前必须完成O0-G的能力协商、事务授权、占用账目及全链回归。

### 5.1 使用和兼容

1. 先在隔离副本演练v32迁移，再按既有运维流程升级指定库。启动仍拒绝未迁移主库；GET不会建表。本轮没有迁移`var/rai.sqlite`。
2. `GET /v1/handshake`返回`coachLoopContractVersion=1`；`GET /v1/mobile/coach-loop`返回policy hash、revision、facts hash及建议/保护信息。未启用时可给只读建议，不冒充已发布课。
3. `POST /v1/mobile/coach-loop`提交`contractVersion=1`、UUID操作键、operationScope、expectedRevision、expectedFactsHash、`action=enable`、当前acceptedPolicyHash和settings。后续使用refresh/update/pause/resume/end；换赛事/模式先结束再启用。
4. `POST /v1/mobile/coach-feedback`自愿保存/撤回感受；新聚合读取能立即安全限制旧课，但不会因此写goals修订。
5. `POST /v1/mobile/coach-prediction-refresh`显式生成摘要；失败不影响核心评分或已有可兼容工件，GET不计算预测或排队。

**当前原生界面仍使用旧合同。**未选新合同时原路径不变；选择后，旧今日/教练/课表/编辑/同步接口返回`coach_loop_contract_required`，防止按旧S裁掉追加或绕过新版门控。新版消费者必须接入新聚合才能实际使用；没有把旧iOS静默升级，也没有冒称设备验收完成。

### 5.2 与初始方案的差异

- 代码中没有可不加改动就附加摘要的统一后台预测报告发布任务；本轮改用显式异步命令复用报告构建器，不在GET写摘要，也不新建后台机制。
- 纯模块仍保留candidate研究标识及原版本，运行层明确接受policy hash后采用固定规则。产品配置接受不等于专业训练策略审阅或医学有效性认证。
- 新旧合同隔离，不偷换weeklyCapacityKm。旧原生消费迁移、实际设备执行一致性须单独验收，不能由API测试代替。
