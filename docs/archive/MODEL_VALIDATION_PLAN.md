# RAI V1 评分模型验证计划

## 1. 当前可用样本

根据实际导出：

| 队列 | 数量 | 定义 | 用途 |
|---|---:|---|---|
| Gold | 36 | Apple Watch 户外、距离 ≥ 1 km、时长 ≥ 8 min、心率可用、配速合理 | 核心公式设计与回放 |
| Extended | 79 | 跨来源 canonical 户外，满足相同核心条件 | 来源偏差和稳健性验证 |
| Heart-rate evidence | 80 | canonical 且有心率统计或合格时间序列 | 心率效率可计算性 |
| Historical context | 252 | 全部 canonical 跑步 | 跑量、停跑和历史上下文，不全部用于拟合 |

36 次 Gold 足够做原型和发现明显错误，不足以支持复杂机器学习或大量自由参数。V1 应采用少参数、稳健、可解释模型。

## 2. 验证目标

模型不是为了拟合出“好看的曲线”，而是同时满足：

1. **区分度**：更高质量的当日表现通常得到更高 CA。
2. **稳定性**：一次异常跑步不会让 TA 大幅改变。
3. **响应性**：持续改善后 TA 能在合理滞后内上升。
4. **来源稳健性**：相同真实训练的不同来源不会产生明显不同分数。
5. **可解释性**：主要驱动与原始指标方向一致。
6. **无数据泄漏**：评分只使用跑步当时及之前的数据。

## 3. 不能直接作为“真值”的数据

- Apple 的 VO2 Max 估计不能作为唯一标签；它本身也是模型输出。
- 卡路里不能作为能力标签。
- 当前 RAI 公式的输出不能再拿来验证当前公式。
- 用户看到分数后填写的 RPE 可能受分数影响，需要标记填写时机。
- 单次平均配速没有控制努力程度，不能直接代表能力。

## 4. 建议采集的验证标签

### P0

- 跑后立即填写 RPE 1～10；
- 训练类型：恢复、轻松、稳态、节奏、间歇、长跑、比赛；
- 状态：正常、疲劳、睡眠差、生病、天气影响、路线异常；
- 是否全力或接近全力；
- 是否存在明显 GPS / 心率异常。

### P1

- 每 4～6 周一次相对标准化的 5 km 或 30 分钟测试跑；
- 比赛结果；
- 主观恢复评分；
- 训练前静息状态备注。

RPE 和标签用于离线验证，不直接修改当次评分。

## 5. 数据切分

必须按时间切分，禁止随机打乱同一个人的跑步：

1. 最早一段用于个人校准；
2. 中间一段用于参数选择；
3. 最近一段作为最终回测；
4. 每次模型升级都保持同一套冻结回测区间。

样本较少时使用 walk-forward validation：

```text
训练/校准 [1..n] -> 预测 n+1
训练/校准 [1..n+1] -> 预测 n+2
...
```

不能用未来 28 天的静息心率、HRV 或睡眠基准计算过去的分数。

## 6. 第一版特征策略

### Efficiency

- 使用相对心率强度下的等效速度；
- 优先稳态区间；
- GPS 路线质量足够时做有限坡度修正；
- 高温、湿度只在 Workout metadata 存在时使用；
- 与个人基准比较，不与人群比较。

### Pace

- 不把轻松跑的慢配速直接视为能力下降；
- 根据持续时间、心率强度和训练类型估计等效输出；
- 近全力测试跑为 Pace 提供更高 evidence strength。

### Cardio

- 有氧持续时间；
- 稳态训练的心率漂移；
- 一分钟心率恢复，仅在数据存在时使用。

### Stability

- 30 秒平滑后的配速、心率和步频；
- 去除热身、冷身、暂停和长期趋势；
- 间歇训练不计算普通 Stability。

### Recovery

- 睡眠、静息心率、HRV 和近期负荷；
- 全部只使用跑步开始前的数据；
- 缺失项重新归一化，不填 50。

## 7. 评估指标

| 目标 | 指标 |
|---|---|
| 下一次表现预测 | 预测等效 30 分钟速度的 MAE / MAPE |
| 排序能力 | CA 与标准测试表现的 Spearman 相关 |
| TA 稳定性 | 单次 TA 变化 P50 / P95 / 最大值 |
| 疲劳隔离 | Recovery 低时孤立低 CA 对 TA 的平均影响 |
| 持续响应 | 连续 3～5 次改善后 TA 的响应时长 |
| 来源一致性 | 同一 duplicate group 不同来源计算结果差 |
| 解释一致性 | 解释方向与特征贡献方向一致率 |
| 数据质量 | 低置信记录进入 TA 更新的数量，应为 0 |

建议的 V1 验收线需要在第一次 baseline 回放后依据真实分布确定，不能在没有输出分布前拍脑袋固定。

## 8. 对照模型

每次复杂模型都必须与简单基线比较：

1. 最近 5 次合格跑步等效速度中位数；
2. 指数移动平均；
3. 单纯速度 / 相对心率效率；
4. RAI 五维模型。

如果五维模型在预测、稳定性或解释上没有明显优于简单基线，不应因为“更复杂”而上线。

## 9. 参数纪律

- 所有参数进入版本化 JSON 配置。
- 评分代码不读取数据库、系统时间或全局变量。
- 同一输入、模型配置和版本必须得到完全相同输出。
- 参数调整必须重放完整历史并生成差异报告。
- 每次只调整少量参数，并记录调整原因。
- 禁止针对某一条不满意的跑步临时加特殊规则。

## 9.1 当前回放基线

当前 active 模型为 `rai-model-config-v2`。其参数调整与真实数据分布见 [MODEL_DISTRIBUTION_REPORT.md](MODEL_DISTRIBUTION_REPORT.md)：

- 心率资格同时接受“足够样本数”或“足够的时间覆盖率”，防止低频长区间记录被错误降级；
- 当前 `cardioRaw` 近似距离，只保留诊断分数、权重为 0；
- `dimensionScoreZScale` 为 10，Efficiency、Pace、Stability、Recovery 权重分别为 37.5%、31.25%、18.75%、12.5%。

这是一套待验证的个人指数基线，不是运动科学上的绝对能力估计。后续参数变更必须重复完整回放并更新分布对照。

## 10. 推荐开发顺序

1. 建立 canonical Workout feature table。
2. 先实现最简单效率基线和置信度。
3. 回放 36 次 Gold，检查异常和数据关联。
4. 加入 Pace 与 Cardio，对比简单基线。
5. 加入 Recovery，只验证负向结果隔离，不直接奖励能力。
6. 最后加入 Stability 和能力贡献。
7. 用 Extended 队列检查来源偏差。
8. 冻结 `rai-v1.0.0-beta.1` 后再开始首页评分展示。
