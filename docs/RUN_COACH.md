# 原生跑步教练

## 对齐对象

对齐新版 **Garmin Run Coach** 的自适应工作流，不是 Jeff/Greg/Amy 专家计划。
参考佳明公开的 [Coach 功能说明](https://support.garmin.com/en-US/?faq=o21H5a4cSU52FwFAy0R6Z5)；不使用其商标、教练肖像、训练视频或私有算法。

## 已实现

| 功能 | 本项目行为 |
| --- | --- |
| 创建计划 | 改善体能、顺利完赛、目标时间；6–52 周，5K/10K/半马/全马或自定义距离 |
| 训练偏好 | 可跑步日、长距离偏好日、配速或心率目标、可选补充力量训练 |
| 原生入口 | 今日页进入跑步教练；概要、比赛倒计时、阶段、今日处方、未来七日、记录与反馈 |
| 自适应 | 打开教练或全量刷新时，以当前训练、恢复、伤病、校准及分区证据生成未来七日 |
| 日常调整 | 更新偏好后重新生成；不提供手工改期，不累积未观测训练的补课债务 |
| 管理 | 暂停、按当前状态恢复、结束、创建新计划；暂停和结束后的未来跑步不可执行 |
| 手表 | 用户显式同步跑步结构到现有 WorkoutKit；暂停或结束后可显式撤回旧排期 |
| 数据一致性 | CAS 修订、事实指纹幂等、配置域隔离、离线只读、保存回执独立缓存、按修订隔离旧课表、保存成功与刷新失败分别报告 |

体能计划默认 12 周，可设 6–52 周；比赛计划按比赛日期结束，新建时需要 42–364 天准备期。
本项目设置至少三个跑步日，长距离偏好必须属于跑步日；这些是本地配置限制，不宣称是佳明限制。
目标类别、赛事距离和结束日期在当前计划中固定，目标时间和训练偏好可修改；更换赛事创建新计划。
偏好不是每周训练次数的保证：校准、跑量、恢复或已完成预算不足时可以减少训练或安排休息。
因此教练页把"这一周排了几次、为什么这么小"提到首屏（校准进度 + 已排次数 + 本周预算），并把「跑步日」改称「可跑步日（可选，不是承诺）」—— 解释是交付要求，不是可选文案。
无历史时仍然给出确定的计划（保守起步 5 km），而不是空态；同时必须说明它是保守起步、不是整个计划的全部内容。

## 服务端政策

[run-coach](../apps/api/src/run-coach.ts) 复用既有结构化训练模板、分区和 `constrainUpcomingPlan`，不在手机重写评分核心。
周容量与读接口使用同一 [weekly-capacity](../apps/api/src/weekly-capacity.ts)：无数据保守重启 5 km；体能计划基于实测四周均值最多增加 10%，仍受上周斜坡、已完成量和恢复闸门约束。
读接口发布的 `weeklyCapacityKm` 是**本周预算**，不是裸容量：它取 `min(容量, 本周量带上限)`（`runCoachWeeklyBudget`），而"本周量带上限"直接取自今天页渲染的 `periodization.current.volumeBandKm.upper` 本身，不是按阶段重算一份。此前读侧发布的是已经过斜坡、却未按阶段裁剪的容量，与生成侧实际使用的数字是两个量（36.75 对 31.5），同屏三个数。
赛事计划由距离和阶段给出政策目标，再受近期实际跑量限制；全马/更长距离的目标基线分别为 45/55 km，不能越过已有证据闸门。
阶段按赛事倒推 base/build/peak/taper/race_week；当前阶段边界及剂量是本项目规则，不是佳明内部周期计算，也不是已验证的全马或超长距离训练方案。
阶段边界**只写在** [plan-periodization](../apps/api/src/plan-periodization.ts) 的 `PHASE_BOUNDARIES` 一处：教练页与今天页都经 `runCoachPhase` 适配器读它，并按自然周（`periodizationWeekStart`）对齐。2026-10-07 之前教练侧另有一套按天推算（`floor(days/7)` 配固定 `taper+5` 的 build 窗口），会给 5K 比半马更长的专项期、并让同一自然周内阶段发生跳变。
自定义距离（如全马）没有骨架，因此**没有阶段**：`phase` 为 `null`、界面显示「持续训练」，而不是给它一个并不存在的「基础期」。

未完成校准时只给基础轻松训练；缺少可用心率上界时不下发心率警报，也不把配速目标伪装为心率目标。
心率偏好在安全闸门和预算裁剪之后统一应用，生成、今日建议与手表导出使用相同目标；裁剪重建不能静默切回配速。
所有赛事距离的比赛日均不追加训练，已保存或锁定的旧训练也不能绕过读侧比赛日保护。
已完成、锁定和迁移保护的今日处方不被重排；历史修订保持原口径。旧未来窗口外的安排不会悄悄残留。
事实指纹不包含排课自身修订或当前墙钟，包含日期、训练量、恢复、伤病、校准、分区及训练限制；相同证据刷新不写新修订。
读接口没有写副作用，自适应由明确的 CAS 命令执行；手机未打开或没有服务连接时不承诺后台每日排课。
保存的七日窗口过期但尚未刷新时，未排定日期保持不可执行，不回退旧模板；读侧也独立执行跑步日和计划结束日期约束。
教练命令已保存但后续读取失败时，概要采用保存回执的修订，旧课表不展示或同步；离线重启保留这份回执。暂停、结束及离线状态下的重试也补读训练安排，不会隐式恢复已暂停计划。

### 备赛信心值（2026-10-07 起）

复刻的是佳明「成绩信心值」的**位置**，语义是本项目自己的：`MobileRunCoachResponse.confidence` 是**备赛准备度**，不是达标概率。数值 = `assessPreparation` 的准备度分（周量 / 长距离 / 频率 / 该距离强度暴露 / 新鲜度的加权和）百分化，五分量随 payload 一起发出，界面据此说明"缺的是什么"，而不是只给一个孤立的分数。`evidenceLevel` 同时出发：历史不足一个完整窗口（`developing`）时，低分不等于低跑量。

三档 `low` / `moderate` / `high` 的分界 70 / 40 是 **policy 常数、未拟合**：没有用成绩标签回放校准过，因此只作文案分档，**不进入任何处方或预测**。

三个闸门，任一不满足 ⇒ `status="insufficient_data"` 且 `value=null`：

1. 距离在预测链内（5K / 10K / 半马）；自定义距离返回 `reasonCodes=["unsupported_distance"]`。
2. 有可用训练记录；否则说明缺证据，**不给 0** —— 0 会被读成"准备度为零"这个断言，与 [@rai/durability](../packages/durability/src/index.ts) 对 `durabilityScore` 的红线同形（"`null` 也不是 0"）。
3. 校准未完成时不允许出现 `high`：没有成绩标签就不能宣称"准备充分"。分数保留，档位降为 `moderate`，并附 `calibration_incomplete_caps_band`。

没有比赛计划（无计划或体能计划）时 `confidence` 为 `null` —— 没有"备赛"这件事，而不是发布一个恒空的壳。

未排课的**跑步日**回传 `unplannedDays`（代码 + 可观测计数），不写动机。生成期那条座位此前一律写「恢复日。」，但同一分支也覆盖被爬坡闸门和赛前策略拿掉的天 —— 那是一句代码从未确立的因果。

## 明确未复刻

- Garmin/Firstbeat 的私有模型、Training Readiness、Body Battery 等专有指标。
- 佳明成绩信心值的**算法**：本项目的 `confidence` 是备赛准备度（见上），不是达标的概率估计。
- **目标可达性**（"按当前预测能不能跑到目标时间"）：契约里 `RaceTimePrediction` 已有 `predictedSeconds` / `confidence` / `confidenceLevel`，但 `/v1/predictions` 由异步且昂贵的报告构建器产出，而教练路由是同步读。接进来需要先定"重算期落小快照"的架构，本次不做。
- 全马及自定义距离的成绩预测和达标保证：目前只有 5K/10K/半马进入校准预测链，自定义距离**同时没有信心值**。
- 佳明设备和 Garmin Connect 同步；当前设备输出是 Apple WorkoutKit 跑步课表。
- 力量动作视频、动作库、力量完成追踪及力量训练到手表的同步。当前仅提供可折叠的基础补充训练，不替代专业指导。
- 官方知识文章、专家教练人格、全训练周期固定处方、佳明的精确阶段长度和训练剂量。

因此这是新版流程对齐，不是佳明算法或完整设备生态的等价复刻。
