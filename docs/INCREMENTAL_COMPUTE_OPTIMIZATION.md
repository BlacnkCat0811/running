# 健康数据增量重算与速度窗口优化

## 本次实现

### 1. 从最早受影响时间重算，而不是健康数据一变就全量重算

完成的导入变更账本结合导入前后的记录，识别心率、速度、静息心率、
睡眠和 HRV 的影响时间。修改时间、修改类型和删除记录均检查旧值，
不单独信任新记录或账本的 effective_at。

- 样本落在训练中间时，回退到该次训练开始。
- 同时比较规范化主睡眠及 HRV 日记录。晚到的睡眠可能替换早上的主睡眠，
  因而使用新旧主睡眠可用时间，而不是只从晚到样本开始算。
- 受影响时间之后的训练仍全部重算，覆盖历史心率上限、恢复基线等后续依赖。
- 每日训练指标仍计算完整时间线；本次不宣称全部计算阶段均已增量化。
- VO2、个人资料、解析契约或恢复算法版本变化、时间异常、未知删除、
  缺失可信账本等情况保留全量回退。
- 健康变更没有任何可复用的历史训练时，直接全量，避免无收益的增量加影子对照。

导入任务 summary 增加可选 `recomputeReasons`，解释重算或回退原因。
复用/重算数量读取实际发布模型对应的特征运行，不再误取最后创建的影子参考运行。

### 2. 加固历史特征和模型检查点复用

复用前检查算法配置、契约、特征版本、时区、训练集合和人工覆盖快照。
新纳入的历史训练、不同的历史覆盖、不同的时区均不能直接沿用旧前缀。
模型检查点还需验证此前特征前缀确实被复用，以及训练顺序一致。

### 3. 速度窗口计算共享时间线

一次建立速度区间事件时间线，60 秒平滑和 30 秒间歇检测共用；
查询只遍历覆盖当前窗口的区间，减少反复过滤全体样本。

刻意保持输入顺序的浮点加法和原有分段，不使用可能改变舍入的滚动总和，
不修改训练分类阈值。重叠非常密集的极端输入仍可能有较高构建开销，
不能宣称所有输入均为线性复杂度。

## 安全策略不变

没有关闭强制模型质量门禁，也没有更改默认影子校验策略。
`shadow` 模式仍额外执行独立全量参考；因此局部复用不保证完整导入耗时缩短。
应分别观察特征、训练指标、模型回放和影子校验耗时。

没有更换生产数据库、修改真实健康数据、操作 FRP 或部署到 N100。
没有新增数据库迁移；旧客户端可忽略新增的可选摘要字段。

## 可复现验证

```sh
npm run typecheck
npm test
npm run build
npm run rust:verify
npm run data:benchmark-speed
```

速度基准为一小时、10Hz、36000 个合成样本，包含时间线构建和
60 秒/30 秒两组窗口。先检查结果完全相等，再交替运行两种算法各五次，
输出中位数和每轮耗时。旧算法基准仅在开始过滤一次有效样本，不人为放大旧实现成本。
它仅测速度窗口计算，不测 SQLite、上传、FRP、完整同步或 N100。

增量集成测试使用隔离合成数据库：10 次训练中常见近期变更复用 8 次、
重算 2 次；最后一次训练之后的静息心率更新可复用全部 10 次特征。
同时执行独立全量影子对照，验证计算一致，而不仅验证任务成功。

### 本地结果

- 全量回归：后端及共享包 705 项通过、3 项跳过；Web 84 项通过。
- 类型检查、Web 生产构建通过；Rust 2 项单元测试和 9 项集成测试通过。
- 补充边界回归 22 项通过，包含记录类型变更、恢复算法版本变化、
  时区切换禁止复用，以及速度窗口精确浮点对照。
- 速度窗口合成基准：原算法中位数 242.06ms，优化后 28.60ms，约 8.46 倍。
  环境为 macOS x64 / Ryzen 5 3600X / Node 22.23.2，**不是 N100**。
  逐轮结果保存在 `docs/benchmarks/speed-windows-synthetic.json`。
- 本次未运行桌面浏览器 E2E 或响应式测试，未修改 Web 界面。

## 目标机器上线验收

1. 停止写入后备份现有数据与配置，先在副本验证，保留原版本用于回滚。
2. 在 2 核 2GB 云服务器上按 `deploy/README-CLOUD-2C2G.md` 部署，
   不迁移 N100，仍维持一个主数据集和串行重型任务。
3. 对新增训练、历史心率更正、睡眠替换、无变化导入分别记录基线与升级后耗时，
   保持相同数据、评估时间和校验模式；额外记录内存及数据库磁盘空间。
4. 首先保持 shadow，确认候选/参考相等及模型质量门禁通过。
   若之后单独评估关闭额外影子校验的收益，必须明确记录模式差异，
   不将关闭校验带来的时间差伪装成算法提升。
5. 通过后再发布；异常先停止写入，按既有部署流程恢复备份与旧版本。

尚未验证的后续瓶颈包括上传/FRP 带宽、数据库副本复制和全时间线每日指标。
下一轮应依据目标机器阶段计时选择工作，不继续无基准地换语言或增加并发写入。
