| 安全降级 | 硬约束使当前有效训练缩量、降阶或不可执行；不是受伤诊断，也不是修改历史事实 |
| 持续训练模式 | 无比赛目标时，以实际训练、能力、恢复与可用时间决定当天训练；不虚构比赛阶段或强制结束日期 |

| 受控追加 | 常规课会超过S或S已完成时，另经资格、负荷、时长、预留量和次数校验放行的一堂完整课；不是自动补课 |

## 1. 总体判断与优化原则

**最值得优化的不是增加更多“佳明式指标”，而是把现有分析能力串成稳定、可解释的训练闭环。**

能力/恢复分离、复合负荷、分区、周期骨架、规则排课、事实快照、发布幂等、排期恢复保护、课表分段、训练后RPE及回放基础已经存在或部分存在。本文补齐语义、执行评价和适应决策，不重建这些能力。

### 1.1 必须保持的原则

1. **先口径与可信性，再闭环与稳定性，最后产品价值。**
2. **硬约束优先，稳定性为次级目标。** 不因保留课表而继续输出违反当前限制的可执行训练。
3. 所有变化必须可追溯到事实、规则、作用日期和前后处方，可解释、可回放、可验收。
4. 缺记录是未知；明确中断也不形成补课债务。非计划训练照常进入负荷，不自动抵扣质量完成。
5. 主观反馈与设备证据并列，不强行合成精确恢复分数，不写回长期CA/TA。
6. 准备度、参考预测、目标差距和预测不确定性各自独立，不输出未校准的达标概率或百分比成功率。
7. 周容量继续由训练事实推导；每天可用时长仅为安排约束，不是能力基线。
8. 继续使用TypeScript服务端算法；读取无写副作用，业务修改走现有CAS/操作幂等/发布协调。
9. 每次决策固定业务时区 `Asia/Shanghai`、事实时点及可得时点；不靠机器墙钟或未来标签补齐历史。
10. 不自动变更设备排期，不新增后台机制。服务端处方变化与现有系统排期是否需要用户更新是两件事。
11. **先决定本次训练意图和完整剂量，再决定本周还能安排几次；不将剩余公里均分给剩余日历天。**
12. **未绑定比赛也必须能持续训练；绑定比赛后增加专项方向，不更换安全引擎。** 每日规则与周期教练不能各排一份相互矛盾的今日课表。
13. **普通自动跑课至少30分钟，放不下就少排或休息。** 30分钟不能覆盖安全限制，也不用于否定用户实际完成的短训练。
14. **周建议量完成不等于必须停跑。** 独立检查追加资格和硬约束；允许有证据地超出建议量，禁止反复刷新、换周、换目标或一次超量触发无限加量。

### 1.2 共享工程约定

以下为后续实现合同，不是已有新增字段。

```ts
type EvidenceRef = {
  source: string;                 // workout/readiness/zone/feedback/policy等
  id: string;                     // 真实记录、快照或规则版本；不伪造ID
  observedAt: string | null;       // 事件发生时刻，未知则null
  availableAt: string | null;      // 系统首次可用时刻，未知则不能认证as_known_then
  revisionOrHash: string | null;
};

type DecisionReason = {
  code: string;
  policyVersion: string;
  evidenceRefs: EvidenceRef[];
  affectedDates: string[];
  params: Record<string, string | number | boolean | null>;
};

type CoachPolicyManifest = {
  contractVersion: number;
  trainingModeVersion: string;
  sessionDoseVersion: string;
  budgetAllocationVersion: string;
  extensionEligibilityVersion: string;
  capacityEnvelopeVersion: string;
  executionProtectionVersion: string;
  executionAssessmentVersion: string;
  adaptationVersion: string;
  templateLibraryVersion: string;
  subjectiveFeedbackVersion: string;
  predictionSummaryVersion: string;
  replayScenarioVersion: string;
};
```

- 语义hash复用既有规范JSON；执行结构hash复用 `prescriptionDigest`。请求耗时、生成时间和解释文本不得制造处方变更。
- 事实快照令牌纳入**实际参与决策**的新事实和策略版本；不能因 `goalsRevision` 相同就断言事实相同。
- HTTP安全字段通过独立能力版本协商；新增枚举/安全语义不能仅“设为Optional”后猜默认值。
- 新增存储只限必要的评价、反馈、决策收据和预测摘要；周量锚点及追加占用附在既有发布/决策记录，不创建完整计划实体体系。历史迁移只追加，不改旧checksum。
- 剂量、匹配阈值等新增常数均为**项目策略候选、未实证校准**。本文给出工程初值；责任人签字、回放通过后才可激活。

### 1.3 新增前置O0：把用户需求变成产品合同

本轮补充需求优先于旧方案中“仅沿用保守模板”“只新增选择、不增加课型”的范围限制。这里新增的是实施任务，不是本轮直接修改业务行为。

| 需求 | 必须交付 | 不能替代它的做法 |
| --- | --- | --- |
| 没有比赛目标也每天给出训练建议 | `daily_adaptive`持续训练，输出当天休息或完整跑课，参考近期真实训练与恢复 | 要求先创建12周fitness计划；仅显示恢复评分；每天固定轻松跑 |
| 普通训练30分钟起步 | 独立的单堂时长合同，在生成、重排、降级、读取有效处方及最终校验均成立 | 把 `easyDurationFloorFraction` 当时长；只改显示数字；加空白步骤凑时长 |
| 周建议20km，周一自主跑10km后不要碎片化 | 常规部分优先安排较少完整课；零头不拆短课，需要超建议量时另走受控追加 | 均分剩余可跑日；凑30分钟时跳过追加资格或硬约束 |
| 周建议20km已完成，后续状态允许继续训练 | 每日重新检查，满足条件时放行完整追加课；返回超建议量和保护余量 | 一到20km整周停课；把建议量改成实际量；只有绿灯就一直追加 |
| 设置比赛目标及日期后专项备赛 | 距离/日期决定阶段与课型方向；完赛/目标成绩决定目标语义，训练仍按当前能力和证据调整 | 为追目标成绩直接提高所有配速；错过课程后补课；压缩全部阶段赶比赛 |
| 轻松、有氧、阈值、LSD、间歇、法特莱克可合理安排 | 两种模式使用同一语义化模板库，满足资格时可选，含整课结构与目标段 | 每周集齐所有课型；换个课名当新模板；把法特莱克强段记为轻松量 |

“低强度”不等于“不值得安排”。本需求解决的是**课表被预算机械切碎**，不是取消轻松/恢复训练。30分钟是用户明确的默认产品要求，不是普遍生理有效性阈值；真实训练不足30分钟仍照常入库、计量与评价。

### 1.4 双模式与生命周期

建议新增显式 `trainingMode: "daily_adaptive" | "race_preparation"`，与既有 `active/paused/ended` 生命周期分开；`programmeId`仍可为null，不为了每日建议建立完整计划实体。

| 状态 | 安排合同 | 迁移/边界 |
| --- | --- | --- |
| 没有比赛目标，也未创建教练计划 | 默认持续训练；`phase=null`，今日有明确决策，未来七日为可调整展望 | 不要求比赛日期、目标时间或至少3个可跑日；未设置可跑日时可作为候选日，不承诺天天训练 |
| 用户主动选择无比赛的持续训练 | 与上行共用决策和容量政策；可设置可跑日、时长偏好及暂停 | 允许1–7个可跑日；未设时长不表示无限容量；不再人为强制6–52周后停课 |
| 已有有期限fitness计划 | 保留原配置、结束日、历史及暂停语义 | 用户明确转换才进入无期限持续模式；不悄悄延长旧计划；转换记录CAS及原因 |
| 有比赛距离和有效日期，目标为完赛或成绩 | `race_preparation`；支持距离使用唯一阶段骨架，近期完成情况调整剂量和后续课 | 无成绩目标也能备赛；不支持距离保持兼容约束及 `phase=null`，不能伪造专项成熟度 |
| 暂停/结束/明确停止 | 不因为“没有活跃比赛”自动开启持续训练 | 恢复训练或转入持续模式需明确命令；停止限制优先于模式默认值 |
| 比赛日期已过 | 赛事结束不等于已参赛；保留既有赛后限制 | 根据实际比赛/训练事实决定恢复限制，用户确认后转持续训练或创建下一赛事；无参赛记录不虚构比赛负荷 |

**创建/更换目标的实施边界：**

- 当前新比赛计划只接受42–364天，当前计划不允许直接改变目标类别、距离或日期（E15）。第一版保留该校验和“结束旧计划→创建新计划”的历史边界；拒绝时明确原因，不宣称支持任意临近比赛。
- 未来若支持少于42天的新赛事，必须单列“短准备期”政策及验收：不压缩补完缺失阶段、不提高容量，不混入本轮兼容实现。
- 仅更改目标成绩可以沿用既有update；它可改变目标差距说明，不能直接改变能力区间或突破剂量政策。不同目标类别的内容偏好由O4版本化配置。
- 创建、结束、转换后的比赛目标只有一个权威来源；旧 `raceTarget` 与旧programme不得残留为两套生效赛事。
- 无计划/fitness目前存在容量增长差别（E15）；O0必须统一同模式的来源选择及政策版本，不能仅因进入了“教练入口”提高预算。

### 1.5 每日自适应不等于每天推翻整周

**同一冻结事实 → 模式/生命周期 → 负荷与恢复约束 → 训练意图/模板 → 时长和预算可行性 → 今日有效处方 + 后续最小修补。**

1. 今天先读取实际训练、最近强度刺激/长课、近期量与负荷、有效恢复/自述、能力与分区及可用时间。已有质量记录即使无法确认原处方完成，也可以按足够的实际强度证据占用间隔/次数；不奖励“跑得更多”。
2. 无赛事不使用伪造的base/build循环：以近期刺激分布和恢复需要选择休息、轻松/恢复、有氧、长课或合格质量课。不只凭“距上次质量课几天”自动加组，更不因缺记录把训练停顿解释为恢复良好。
3. 有赛事在相同流程上增加日期、距离、阶段和赛前保护。未来日期只有暂定计划，不能把今日好恢复复制成未来七天的许可。
4. 已完成今日训练默认不再追加第二堂；自主训练全部计入事实和剩余容量。原处方仍保留用于复盘，不能事后新建处方来宣布完成。
5. 跨上海本地日、新训练导入/撤回、恢复/反馈/分区或目标变更触发重新评估；事实变了不代表执行结构必须变化。O3负责已发布安排的最小修补。
6. **今天的无计划建议允许按冻结输入只读推导，不在GET写库；已有发布计划的重排必须走显式命令。** 前台打开/刷新或数据更新后的既有交互流程可提交幂等刷新命令，再读取同一修订，不新增定时后台任务。
7. 无programme的持续模式必须增加可用的刷新命令路径：可扩展既有周计划发布服务，接受 `programmeId=null` 和模式配置，不为调用 `/run-coach refresh` 强造一个12周计划。是否需要刷新由业务日期、事实hash和策略manifest判断，不依赖每周一自动生成条件。
8. 有效读取可立即安全降级旧处方；需要新增/升级/移课而尚未成功发布时，返回 `refresh_required`，不让不同入口各自生成可执行替代课。无计划推导建议与“已保存/已排期”明确区分；导出前经过发布与快照校验。
9. 离线、刷新失败、窗口过期要明确状态；不假装已经完成今日自适应。未打开应用且服务不可达时，不承诺每天后台写课或同步手表。

今日推荐、周生成、周期教练、有效执行读取必须共享纯决策核心及最终校验；允许入口提供不同上下文，不允许重复维护30分钟、预算与课型资格的不同版本。

### 1.6 30分钟与整课剂量合同

建议新增独立版本化 `minimumSessionDurationSeconds=1800`，作用于系统自动新生成/调整的普通跑课，包括easy/recovery/aerobic/long/threshold/interval/fartlek；rest没有时长下限。

- 默认口径为**整堂有明确目标的训练时长**：热身、工作、计划内恢复、整理计入；暂停、开放式等待、附加力量训练不计入。不是强制质量工作段连续30分钟。
- 每个模板另有 `minimumWorkDose`（工作秒数/米数/组数），须在模板manifest审批。不能用29分钟热身加1分钟工作把无意义结构包装成阈值课；质量课被裁到意图不成立时换课型。
- 时间优先：普通课优先构建可执行的时间目标；km为预算核算估计，标注分区/配速来源与不确定性。30分钟按1800秒校验，显示四舍五入不能让1799秒通过。
- 距离目标模板按**各步骤目标配速允许范围**估计总时长区间：下界不小于1800秒，上界不超过用户可用时长；不只用最慢配速保证30分钟。无法可靠估计时改成有界时间结构或返回不可评估，不把默认配速称为真实能力。
- 时间模板的km成本按版本化保守估计（可用目标范围的较快端）核算；未知分区只可使用明确标注的冷启动估计政策，不输出虚假精确配速。实际导入量最终按事实替换估计，误差本身不伪装成用户违规。
- 最终检查在阶段减量、预算裁剪、恢复降级、分区适配之后进行，且所有读取/执行路径一致。不能生成30分钟，随后读侧缩成16分钟却继续标“满足下限”。
- **独立硬余量、恢复或可用时间不能满足30分钟时，自动建议休息并给出冲突原因；不越过安全限制强补时长。** 仅S剩余不足不直接休息，应先检查§1.7的追加路径。用户只有20分钟可用时仍不自动输出20分钟跑课。
- 第一版不默认启用“恢复跑/赛前开腿可低于30分钟”例外，避免把例外变成预算补丁。未来允许例外需用户明确选择、独立类型/理由/上限及验收，不能作为本次30分钟保证的隐藏漏洞。
- 人工保存、锁定的短课保留原文，不强制延长或改写；有效层标注与当前自动处方政策不一致，不宣称符合新保证，按现有人工确认/执行政策处理。实际完成的短训练正常计入负荷，不因本产品下限判无效。
- 冷启动5km上限与30分钟可能冲突：优先保留上限，选择有依据的可行时间课；无可行解则明确 `minimum_session_not_feasible` 及所缺数据/偏好，不自动抬高5km或偷偷下调30分钟。该冲突必须进冷启动验收，不能仍无条件承诺“一定有跑课”。

### 1.7 周建议量与保护上限分离：达到建议量后逐次追加

**新合同：20km是本周常规训练建议，不是“用完就禁止跑”的配额。** 达到20km后，系统仍评估今天；在历史基础、实际负荷、恢复和独立保护上限均允许时，安排新的完整课。只允许在有证据的范围内追加，不承诺周一跑20km之后一定还能跑。

#### A. 三层量：建议、硬边界、本次执行

| 层次 | 字段/含义 | 使用方式 |
| --- | --- | --- |
| 常规建议量 | `suggestedWeeklyKm`，记为S | 选择常规课和大致频率，允许未完成或有理由地超过；不能用于 `actual >= S => rest` |
| 处方保护边界 | 自然周 `weeklyProtectionKm`、滚动7/14日及单堂限制 | 由历史与政策独立推导；所有自动课都必须满足，不因还有建议量、恢复好或目标激进而放宽 |
| 当前预计执行量 | `actualKm + reservedKm + candidateKm` | 实际训练替换相应预留，加入候选后做整个相关窗口的可行性判断；不是先批准再看是否超界 |

“额外”仅指超出常规建议安排，不是另一类生理负荷；自主跑、人工计划、已发布追加课全部进入同一实际量/预留量账本。追加课也不改变原建议量：例如仍返回“建议20、实际20、本次预计5、执行后预计25、保护上限26”。

#### B. 保护上限怎么得到：不能只把旧20km改名为H

现有 `weeklyCapacity → weeklyPlanVolumeCeiling → phaseBand` 把政策目标和保护上限混在一起（E15/E18）。O0须在**唯一容量模块**拆分来源，不能在每日教练里额外加一个“允许超量”布尔值，然后仍被周校验器按旧20km裁掉。

以下是第一版**可离线评审的工程初值**，不是经验证的伤害风险阈值，也不是本文件即可激活的训练建议：

1. 以固定上海自然周之前的完整训练事实建立 `capacityAnchor`：B为最近四个完整自然周均量，P为上一完整周量；保留输入hash、历史截止日及策略版本。本周已跑量、处方计划量、目标配速、恢复分数不能作为提升该锚点的输入。
2. 追加路径要求历史负荷可评估，初值为至少覆盖28日且至少8个不同日期有有效跑步记录，B/P均大于0，并通过既有负荷数据充分性判断；“覆盖28日”不等于把没有记录的天自动确认休息。缺前置时关闭追加，不提高冷启动容量，正常保守建议仍可用。
3. 候选历史保护量 `Hbase = min(B × 1.30, P × 1.30)`；1.30只复用现有增长限制常数作为待评审起点。**不再使用目标量一半的斜坡基线兜底来抬高追加资格。** 不能把已用尽的S再代入旧 `min(S, ramp)`作为H，否则拆分无效。
4. `Hweek = min(Hbase, explicitPhaseHardCap)`，并保留适用的现有产品绝对上限。普通base/build/peak的现有量带用于常规建议S，不继续把同一建议量带当作追加终止条件；长课上限、质量次数/间隔仍是硬约束。**这是明确的策略变化**，激活前更新D13–D16及现行算法合同，而非宣称旧行为完全没变。
5. taper、race_week、赛前14天执行保护、比赛日及既有赛后限制不能被追加绕过；第一版在这些保护生效时不开放超S追加，并保持原相应量带/单堂上限。无骨架的持续模式可以追加；无骨架的赛事模式缺少已审批专项保护时不开放追加。
6. 第一版滚动上限候选为 `H7 = Hbase`、`H14 = 2 × Hbase`。对每个受影响日期d，计算上海日期闭区间 `[d-6,d]`、`[d-13,d]` 内的已知实际量、有效预留量和新课估计量；纳入窗口外已保存课，不只看今天或自然周。最近28日和原有复合负荷/增长标记继续参与判断，不能只要km过关就追加。
7. S优先沿用既有常规目标来源，但统一无计划与fitness入口的政策；输出的常规计划不得超过H。无历史/久停跑等不具备追加资格时，沿用现有保守上限而不是得到 `Infinity`；此时S/H可以相等，明确“追加证据不足”，不能让健康历史充足场景也永久S=H。

**锚点防自我加码：** 同自然周锚点不因本周刚跑完一堂而升高。已知历史的补录/撤回需要显式新证据和新锚点修订，不能因锚点hash变了就重置追加账本。下周基于新的完整历史重新评估，已执行追加可进入真实历史，但不是“一次完成=自动升档”；滚动负荷、次数与所有既有门控继续检查，处方/未执行计划不能充当历史。

未来七日只使用当时已知历史，不把“预计本周会跑完”代入下周B/P。下一周尚未形成新锚点时标注暂定来源，按已知边界保守生成，跨周后显式重评；更换比赛、模式、软件版本或反复重启均不能重置尚在滚动窗口内的负荷及追加占用。

#### C. 达到S以后，什么情况下可以追加

第一版不是“green就加课”。必须同时满足以下条件，且**资格与最终硬约束分开报告**：

| 检查 | 放行条件 | 不满足时 |
| --- | --- | --- |
| 生命周期/意愿 | 当前允许训练、今天是可跑日、没有明确休息/停止请求 | 休息，不因超S或恢复好重启 |
| 今日执行 | 今天尚未完成跑步；没有另一堂可保留的今日跑课或待执行追加课 | 保留已有课/已完成状态，不给第二堂 |
| 事实可用性 | 同一快照内历史负荷可评估；已知最近训练已导入，无待处理的已知训练导入/失败冲突 | `insufficient_evidence`，不把无数据说成低恢复；不能保证发现所有未记录自主训练 |
| 训练与恢复限制 | 逐项评估当前负荷、恢复及有效反馈；没有高负荷、跑量突增、异常应激、集中质量、有效不适/停止等阻断 | 不超S追加；正常计划也按对应限制降级 |
| 单次异常 | 最近一次跑量/时长没有尚未解除的异常单次暴露限制；比较的历史必须截止于该训练之前 | 不用这次20km证明“已经习惯20km”，也不因睡眠好自动解除 |
| 课程条件 | 30分钟完整低强度课有可表达的结构、可靠剂量估计、合格分区/历史与足够可用时间 | 休息/说明缺口，不变成短课 |
| 全窗口可行 | 加入后自然周、滚动7/14日、单堂及强度间隔、所有有效预留均满足硬约束 | 返回具体命中边界及余量，而非笼统“周目标完成” |
| 次数与阶段 | 满足下述逐次授权次数、阶段及赛前保护 | 不提前批准后续课程或突破阶段限制 |

实施时不能只复用 `verdict.tone` 或原来仅用于禁止质量课的少数flag：它们未必覆盖低强度追加的全部条件。要复用底层证据和规则函数，新增统一的 `assessExtensionEligibility`；策略初值将E17中有效的高负荷/跳量/应激/单调性/睡眠异常标记列为追加阻断，并逐项审查，不复制另一套恢复分数。

单次暴露补充初值：对最近7个本地日内每次已知跑步，以该训练发生前56日的有效**单次**距离最大值作参考；超过其1.2倍时标记追加阻断，缺参考则为证据不足而非通过。7日窗口退出后仍须重新通过其他条件，不宣布“自动恢复”。1.2沿用现有距离跳升比较常数作候选，但改正参考时点/粒度（E19）；7/56日窗口同样需审批。时长、RPE和实际强度仍进入原有负荷路径，不能只用平均配速断言低负荷，也不新增未经审批的“伤病概率”。

缺HRV/睡眠设备不自动判恢复差，也不强制佩戴全部传感器才能追加：如果训练历史和负荷证据充分、没有已知不利信号，可以标注“未结合完整恢复监测”继续判定；**缺负荷历史、已知训练未同步或有效停止要求不能用‘没发现异常’替代。** O5尚未实现时不要求提交新主观字段；已存在的明确停止状态仍必须遵守。

#### D. 追加什么、追加多少、如何防止天天越加越多

- **第一版只放行一堂30分钟完整轻松/低强度有氧课**，须满足相应模板最低工作剂量；不借追加机制增加阈值、间歇、法特莱克强段或LSD。其他课型仍可在两种模式的常规计划中合理选择。将来开放更长/更强追加需新策略版本，不静默扩大本版。
- 每次只为**今天**作决定；未来可能追加的日期仅为不可执行展望，不占用已批准课程身份，不把今天状态好当作周四/周六都获准。今天发布前冻结事实，执行前在既有有效读取中重新检查限制。
- 初值：系统一天最多安排一堂自动跑课，已有实际跑步时不再追加第二堂；不禁止记录用户自主完成的多次训练。任一滚动7个本地日内最多**2堂系统批准的追加课（已完成+仍有效待执行）**。这是产品保守限额，不是推荐每周必须加两堂。H可能只容纳一堂或零堂；日期跨周不重置。
- 优先保留/移动一堂合适的既有常规课，而不是把同一训练复制成追加课。S尚有完整常规课额度且未来已有有效常规预留时，先重排或替换，不新增超S课程；S已实际完成或只剩不足一堂的零头时，才进入追加路径。
- 自主跑导致原有未来常规课总量越过S时，先最小修补。失去常规额度的未来课不能继续以“旧课”身份自动执行；保留原文/历史，待到训练日重新评估为追加、降级或休息。今天已有合适课程可转换为本次追加，必须登记资格与占用，不能先发新课后再删除旧课。
- 次数按数据域、实际作用日期和稳定的决策槽位记账，复用发布/适应收据；换operationId、重启、重新生成、移动课程不能多出额度。同一天同一未执行课的结构修补不算新的一堂，移日需释放旧有效占用并保留移动链。
- 完成后用真实训练替换预留，保持已完成追加次数；不能因为“待执行列表清空”又认定当天没排过。安全撤销或未执行过期可释放未执行占用，但已执行不释放；若既有设备旧排期状态仍未协调清楚，不将那份课当作已经消失。
- 追加后恢复/负荷恶化，限制立即作用于未执行课；未来不形成“既然批准了就必须跑”的义务。漏练不追补，超S不奖励加组，S剩余零头也不转为下周债务。

#### E. 两本账与预留：超过S可以，超过H不可以

```text
建议账：suggestedRemaining = max(0, S - actualWeekKm - regularReservedKm)
        actualOverSuggestion = max(0, actualWeekKm - S)
保护账：headroom(window) = H(window) - actual(window) - allEffectiveReserved(window)
候选通过：candidateCost(window) <= headroom(window)，并满足资格/次数/其他硬约束
```

`regularReservedKm`只含常规课，`allEffectiveReserved`还含人工有效预留及已批准追加；同一处方只能计一次。S剩余为0仅表示进入追加评估；H余量为0、任一滚动窗口已超H或没有完整课空间，才阻止新的自动跑课。历史实际超H如实记录，停止新增，不删训练、不抬H追上实际。

保留量含窗口外未完成课及锁定待执行课。实际训练替换/释放相应预留，不双扣；当天已有自主跑而不再执行原自动课时释放其预留，但质量完成仍可能未确认。锁课原文保留，有效层仍受H约束；无法执行的存储原课不得假装已占用可花额度，同时也不能忽略尚有效的排期风险。

所有公里成本按未四舍五入的结构估量计算。旧 `VOLUME_CEILING_TOLERANCE=1.05` 不是追加空间；人工兼容容差与新硬边界分别处理。H不能因为30分钟课差0.3km放不下就提高；也不能把30分钟显示保持不变、实际结构缩到25分钟。

#### F. 聚合合同、原因与兼容

建议扩展同一 `training-plan-state`，各入口消费同一结果：

```ts
type CoachVolumePolicy = {
  schemaVersion: number;
  asOf: string;
  weekStart: string;
  timezone: "Asia/Shanghai";
  anchor: { id: string; revision: number; factsHash: string; historyThrough: string };
  suggestedWeeklyKm: number;       // S，不随超额跑步偷偷改成实际量
  weeklyProtectionKm: number;      // Hweek，不是对用户身体的安全保证
  rollingLimits: Array<{ days: 7 | 14; ceilingKm: number }>;
  actualWeekKm: number;
  regularReservedKm: number;
  extensionReservedKm: number;
  otherReservedKm: number;
  suggestedRemainingKm: number;
  actualOverSuggestionKm: number;
  constraints: Array<{
    code: string; from: string; to: string;
    actualKm: number; reservedKm: number; candidateKm: number;
    ceilingKm: number; remainingBeforeCandidateKm: number; passed: boolean;
  }>;
  extension: {
    status: "not_needed" | "eligible" | "blocked" | "insufficient_evidence";
    assessedForDate: string;
    candidatePrescriptionDigest: string | null;
    authorizedDecisionRef: string | null; // 只读评估通过不等于已发布
    approvedSessionsInRolling7Days: number;
    maximumSessionsInRolling7Days: number;
    reasons: DecisionReason[];
  };
  policyManifest: CoachPolicyManifest;
};
```

- 原因至少区分 `suggested_volume_met`（信息，不是禁跑）、`extension_allowed`、`extension_evidence_insufficient`、`weekly_protection_reached`、`rolling_load_limit`、`recent_single_run_spike`、`recovery_restriction`、`extension_count_limit`、`minimum_session_not_feasible`、`pre_race_extension_blocked`。每条都带实际输入和版本，不能输出“你今天感觉不错，所以多跑”。
- 当H有空间但追加不通过时，同时返回“周建议已完成”及真实阻断原因；不能用“本周预算已完成”遮住真正条件。拒绝一次不等于整周永久禁跑；到下一日期/新事实后仍重评，不绕过仍有效的硬限制。
- S/H、锚点修订、跨周实际/预留、追加收据及资格版本进入事实令牌和适应指纹；批准通过现有CAS/单写者/发布事务登记，失败不消耗次数、不留下半份可执行课。GET不写资格收据或触发后台排课。
- `weeklyCapacityKm` 等旧字段保持旧合同语义，不悄悄改成S或H后让旧消费者猜。先上线新能力版本和必要协议消费，再激活追加；不支持新合同的消费者只能走明确标注的旧限制输出或阻止追加课执行，不能同时宣称看到了当前完整计划。
- `buildCoachWeekPlan`用S构建常规候选；`constrainUpcomingPlan`及每日/有效读取用同一H和授权记录校验最终可执行集合。不能只修改 `decideNextSessionDecision`，否则剩余入口还会删掉追加课；也不能把H直接交给常规生成器让它在周初填满全部保护空间。
- 目标时间、准备度百分数、比赛倒计时不用于提高H。普通阶段量带成为S的变更需明示版本；旧14天保护与减量上限仍保留，和O1的语义统一分开验收。

#### G. 固定正反算例：必须真正出现“20km后还能排课”

下表仅为冻结输入的工程验收，不是给用户的个人训练建议。例中30分钟结构的保守估计固定5km；S=20，B=P=20，按候选公式得到Hweek=H7=26、H14=52。除另注，历史资格/单次暴露/负荷/恢复/时间/阶段均通过，未完成预留0，滚动7/14日加入候选后均不过界。

| 情形 | 合格结果 | 不合格结果 |
| --- | --- | --- |
| 周一已跑10km，S尚余10km | 常规部分可排较少完整课，不均摊成短课；后续达到S后仍可再评估 | 预先把额外6km保护空间也当作本周必跑量 |
| S尚余2.6km，H还有足够空间 | 追加资格通过时可批准30分钟/5km；未通过则休息，不凑2.6km | 只因S零头不足就提前返回休息；或给16分钟课 |
| 周一已跑20km，周四重新评估通过 | 周四批准30分钟/5km，预计周量25，S仍20，记录一堂追加及理由 | 仍因 `actual >= S` 整周停课，或把S篡改成25 |
| 上行追加已完成，再请求一堂5km | H只余1km，不再追加；不能缩成6分钟或把H提高到30 | 把刚完成5km加入当周锚点、再次扩大H |
| 周一20km明显超出此前单次历史，或后续负荷/恢复不利 | 阻断追加；返回具体证据并在后续新事实时重评 | 只因H尚余6km或睡眠好就追加 |
| 已跑22km，H=26 | 只余4km，容不下该5km结构，休息；22km事实保留 | 将超建议量本身当唯一拒绝理由，或自动抬H |
| 已跑22km，另一个历史充分场景H=32，其余门控通过 | 可以批准完整5km课；不得仍按S=20停止 | 所有 `actual > S` 都被旧裁剪器强制清空 |
| 当周已20km且H=26，但跨周滚动7日另有10km | 滚动窗口阻断追加，即使本自然周账面仍余6km | 周一清空过去六日负荷后继续加课 |
| 实际量已越H、冷启动、已暂停或赛前保护生效 | 不追加，分别给出真实原因 | 一概改称“完成周目标”，或绕过保护继续凑30分钟 |

**本版通过的必要条件：**正例“20km完成后批准30分钟完整课”必须成功到达聚合读取和可执行结构；只有“拒绝额外训练”的负例全部通过，不能算完成本需求。

| AC0-21 | 周初常规生成、新旧消费者、目标/阶段政策变更、相同结构从不可执行变为授权 | 常规只围绕S排课；新合同支持后才激活；旧字段不偷换；授权状态变化不能被no_change吞掉 |
| AC0-22 | 历史补录/撤回改变锚点、并发发布、换数据集、故障/回滚 | 显式新锚点修订和来源；已批准/已完成追加账目不丢；CAS拒绝旧事实，失败无半授权/占用 |

反向验证至少包括：将30分钟改回2km；剩余天均分；只改显示时长；达到S直接停课；删除H/滚动检查；将本周实际抬入锚点；周一重置追加次数；绿灯直接放行；候选自证单次历史；把H交给周初生成器；暂停后自动恢复。均需编译通过而被行为断言拒绝，且AC0-13正例不能被保守全休息蒙混通过。

回滚：可关闭追加资格能力，明确返回 `extension_policy_disabled`，保留锚点/事实/收据/已完成追加；对已批准未执行课重做有效限制，不倒退历史。回退后可能暂时只提供常规课，但必须披露能力关闭，不能宣称仍满足“达到建议量后可追加”。**已启用30分钟合同不能回滚成静默短课**；旧生成器仍走公共剂量出口，无法满足时返回休息/原因。原设备排期继续走既有显式协调，不假装已自动撤回。

## 2. 优化项 1：统一“所处阶段”与“实际执行策略”

### 2.1 当前问题

E02/E03及SYN-01确认：阶段骨架按距离和自然周推导，部分执行路径另以“距比赛不超过14天”回答 `taper`。

本质是两个不同作用域共用阶段词汇。可以有“处于peak，但触发赛前保护”，不能同时宣称“处于peak”和“处于taper”。当前证据确认语义不一致，不确认保护规则本身错误。

### 2.2 目标

- 阶段只由E02定义；教练、生成和执行读取相同结果。
- 附加限制统一命名“赛前执行保护”，包含明确触发条件、范围和版本。
- O1单独适配时**保留原14天执行限制的行为**，先消除歧义，不顺手放宽剂量。与O0一起激活时，若旧减量结果不足30分钟，最终出口按O0换课/休息；这属于显式的新剂量版本差异，不要求与旧短课字节相同。
- 若后续确认14天规则不需要独立存在，再单独版本化收敛到骨架，须另做行为差异评审。

### 2.3 建议方案

#### A. 合同与优先级

```ts
type ExecutionPolicyContext = {
  localDate: string;
  phase: "base" | "build" | "peak" | "taper" | "race_week" | "past" | null;
  phasePolicyVersion: string;
  protections: Array<{
    code: "pre_race_execution_protection" | "race_day_no_extra_training";
    policyVersion: string;
    active: boolean;
    daysToRace: number;
    scope: "current_day";
    constraints: Array<{
      kind: "replace_quality_with_easy" | "cap_distance" | "no_extra_training";
      value: number | null;         // 复用原路径计算值，不新造剂量
      unit: "km" | null;
    }>;
    reasons: DecisionReason[];
  }>;
};
```

每个未来日期以该日期重算 `current_day` 的保护；不能把今天的恢复或保护状态直接复制给未来七天。

| 顺序 | 判据 | 对有效处方的影响 |
| --- | --- | --- |
| 1 | 比赛日、结束/暂停、明确停止要求 | 不追加训练；读侧不可被锁课或旧结构绕过 |
| 2 | 当前有效安全/恢复限制 | 降级或阻止执行；历史和存储锁课原文保留 |
| 3 | 自然周/滚动保护上限H、追加授权、单堂时长/模板最低剂量、可用时间、长课上限、质量间隔、校准/分区资格 | 必须同时满足；S不是这一层的停止条件；冲突时休息，不为凑课抬H |
| 4 | 骨架阶段 | 选择候选、阶段预算；它不是强制训练任务 |
| 5 | 附加赛前执行保护 | 对上述可行方案进一步收紧，不改变 `phase` |
| 6 | 稳定性偏好 | 仅在满足前五层的方案间比较 |

该表表达约束关系，不要求重复执行多套裁剪器。同一责任只裁剪一次；保护作为幂等上限或替代规则应用，禁止反复乘减量系数。

#### B. 14天规则与冲突处理

| 条件 | 阶段 | 第一版执行行为 | 必须给出的理由 |
| --- | --- | --- | --- |
| 支持距离，距比赛15天 | 骨架返回值 | 不触发14天附加保护；其他限制仍有效 | 若有变化，说明真实的其他约束 |
| 支持距离，距比赛14至1天 | 骨架返回值，可能仍为peak | 复用现有赛前执行限制 | `pre_race_execution_protection`，带天数和原/新处方 |
| 比赛日 | 骨架返回值 | 不追加训练 | `race_day_no_extra_training` |
| 比赛已过 | 骨架返回值或既有周期结束状态 | 沿用既有结束/恢复行为 | 不声称比赛已完成 |
| 无骨架的体能/自定义距离 | `null` | 保留既有兼容保护；不新增距离模型 | 说明无骨架，不补造base阶段 |

解释样例仅规定API返回语义，不规定任何页面：“当前阶段为强化期；距比赛14天，触发赛前执行保护，原间歇处方调整为轻松训练。”

| O1-B | 从E03收敛到单一执行保护函数；`racePlanPhase`只保留兼容适配，不再对外表达第二阶段 | O1-A |

## 3. 优化项 2：把“当天跑过”与“质量课完成”分开

### 3.1 当前问题

E04/SYN-02确认，质量课日期有跑步记录就增加 `qualityObserved`，未检查组数、刺激或强度。

这不是没有训练分析能力：E05已经具备分段、真实步骤和处方关联基础；E03还有刺激匹配。缺的是一个明确、可查询的三层执行评价及其接入规则。

### 3.2 目标

1. **有无观测**：训练是否有记录。
2. **剂量执行**：处方要求是否有测量支持。
3. **刺激匹配**：实际强度是否符合意图。

“质量课完成”只能由明确关联的处方、足够剂量及匹配刺激共同支持。未知不算完成，也不自动算漏练。恢复跑不能以速度高低排名。

### 3.3 建议方案

#### A. 三层数据结构

```ts
type WorkoutExecutionAssessment = {
  version: string;
  localDate: string;
  asOf: string;
  planRevision: number | null;
  prescriptionDigest: string | null;
  workoutIds: string[];
  association: {
    status: "matched" | "ambiguous" | "unmatched";
    method: "measured_steps_with_plan" | "valid_receipt" | "plan_history" | null;
    evidenceRefs: EvidenceRef[];
  };
  observation: "observed" | "unknown";
  evidenceLevel: "measured_steps" | "reconstructed_segments" | "summary_only" | "none";
  dose: {
    status: "met" | "partial" | "not_met" | "not_assessable";
    requiredDistanceMeters: number | null;
    observedDistanceMeters: number | null;
    requiredWorkSeconds: number | null;
    observedWorkSeconds: number | null;
    requiredReps: number | null;
    verifiedReps: number | null;
  };
  stimulus: {
    status: "matched" | "too_hard" | "too_easy" | "not_assessable";
    channel: "pace" | "heart_rate" | null;
    validCoverageFraction: number | null;
    timeInTargetFraction: number | null;
  };
  completion: "confirmed" | "known_not_met" | "unconfirmed" | "not_applicable";
  reasons: DecisionReason[];
};
```

- 处方关联复用E05及既有回执有效区间。排期回执不是训练完成证据；不能把撤回后的旧回执当作当前处方。
- 不将同日多次训练简单合并成一次间歇课；同一训练不得重复抵扣两份义务。
- 无实际组界时 `verifiedReps=null`，不是0；计划重建的组数不能自证完成组数。
- 训练发生后创建的新处方不用于判定该训练“完成”；沿用历史冻结口径并明确关联的不确定性。

#### B. 证据等级与可用结论

| 等级 | 可支持 | 不可推断 |
| --- | --- | --- |
| `measured_steps` | 有效实测边界上的工作剂量、组数和目标区时间；仍需信号覆盖 | 有步骤就等于强度达标 |
| `reconstructed_segments` | 连续课的实际总量比较；有覆盖时的匹配参考 | 用处方重建的分段证明所有间歇组完成 |
| `summary_only` | 当天有训练、明确匹配连续课时的总量；来源标明 | 从平均心率或总里程证明组数和目标刺激 |
| `none` | 无记录/无证据的原因 | 缺记录就是漏练 |

这里的“真实步骤 > 计划重建 > 汇总”是结论权限层级；高层证据坏覆盖时仍应降为未知，不按等级机械加分。

#### C. 课型评价矩阵

| 课型 | 剂量重点 | 刺激重点 | 确认条件与禁止事项 |
| --- | --- | --- | --- |
| 间歇 | 实测工作组、每组剂量、恢复步骤是否可辨 | 按处方工作段目标；短间歇不拿全程平均心率硬判 | 缺真实组证据保持未确认；轻松跑不能算间歇完成 |
| 节奏 | 有效工作时间/距离，支持步骤不抵扣工作剂量 | 工作段目标区占比 | 总时长足够但工作段不足不能确认 |
| 轻松 | 连续工作剂量及额外训练部分 | 是否维持低强度 | 超速可报过强，不加“完成质量”奖励 |
| 恢复 | 合理完成原剂量，而非距离越多越好 | 低强度意图 | 配速更快、跑得更多不能改善匹配结论 |
| 长距离 | 连续完成量与测量覆盖 | 原定低强度/稳态意图 | 完成距离不等于耐久能力已校准 |
| 休息 | 不适用 | 不适用；记录实际训练进入负荷 | `completion=not_applicable`，不把没跑称为完成跑课 |

**第一版工程初值，须在O2-A评审冻结：**

- 连续工作剂量达到处方工作目标的90%才可标 `met`；等于90%通过，小于90%不通过。
- 间歇要求核验组数达到处方组数，且每个被核验工作组达到其剂量90%；不能用一个长组抵扣两个短组。
- 刺激评价要求对应通道有效覆盖至少80%；匹配须有效工作时间中至少80%处于允许目标集合。
- 覆盖不足或缺目标范围均为 `not_assessable`，不得判 `too_easy`。
- 超出目标区时须有足够覆盖才能判断过强/不足；不以区间外比例直接作生理诊断。
- 间歇的目标通道、心率滞后处理复用现有分区/处方规则；目标通道无法可靠评估则不确认刺激。

以上数字是评价容差候选，不是训练剂量建议、医学阈值或已校准标准。不同课型若需要改阈值，必须显式版本化，不静默共享另一课型的规则。

#### D. 依从性、查询与决策接入

- 保留 `qualityObserved` 的旧计数语义作为兼容字段，新增 `qualityConfirmed/qualityKnownNotMet/qualityUnconfirmed`，分母为真实存在的处方义务。
- 原始训练量、计划日期观测量、已确认质量剂量分开查询；休息日的实际训练进入全周负荷，但不偷换处方完成。
- 新评价接入后，重排判据不再用 `qualityPlanned-qualityObserved` 推导“没完成”；未知只产出证据缺口理由。
- `known_not_met`可使后续剂量保持或降阶；不触发补课，不因 `confirmed`一次成功就自动提高全部区间。
- 建议只读 `GET /v1/mobile/coach-execution?from=…&to=…` 返回评价集合及asOf/事实身份；用于复盘查询，不能把不同asOf的集合拼成当前决策输入。
- 当日评价参与聚合决策时纳入同一冻结读取及令牌；独立复盘接口不写评价、不写计划。

协议解释样例：“有训练，但未确认完成间歇处方。”附原因如 `stimulus_mismatch` 或 `rep_evidence_unavailable`，不设计桌面呈现。

#### E. 工程拆分

| 任务 | 交付与落点 | 依赖 |
| --- | --- | --- |
| O2-A | 三层合同、关联优先级、容差表、兼容指标定义；逐课型审批 | E04/E05、O8-A |
| O2-B | API侧纯评价函数，建议文件 `apps/api/src/coach-execution-assessment.ts`；复用分段/分区，不读取墙钟 | O2-A |
| O2-C | 依从性、重排判据和只读查询接入；评价从冻结事实派生 | O2-B |
| O2-D | 多训练/弱证据/迟到/历史处方测试及R02/R04/R05回放 | O2-C |

### 3.4 验收标准

| ID | 输入/边界 | 预期 |
| --- | --- | --- |
| AC2-01 | 间歇日实际记录为轻松跑 | 有训练，质量未确认；理由可查询 |
| AC2-02 | 处方日无记录 | 观测未知；剂量/刺激不可评估；不判漏练 |
| AC2-03 | 实测组数与剂量充分，但缺强度覆盖 | 剂量可达标，刺激不可评估，完成未确认 |
| AC2-04 | 同样总里程，有/无真实组证据 | 无组证据不能借计划重建确认间歇完成 |
| AC2-05 | 工作剂量89.9%/90%；通道覆盖79.9%/80% | 容差边界按版本表；未知不强行计为不达标 |
| AC2-06 | 恢复课实际强度高于允许范围 | 不因更快获得更优刺激匹配 |
| AC2-07 | 同日两次训练，只有一次有有效处方关联 | 不合并虚构组数，不重复抵扣 |
| AC2-08 | 质量课记录迟到、旧回执已撤回、同日事后改课 | 按可得时间和有效区间评价，不改写历史决策 |

关联回放：R02、R04、R05、R11。反向验证：无记录改为漏练、重建组当实测组、任何跑步增加确认数，分别必须失败。

### 3.5 风险与回滚

- 风险：新确认数低于旧观测数，被误读为训练退步；真实步骤覆盖不足会增加“未确认”。
- 回滚：评价保持可查询及原版本标识，关闭其适应输入时返回兼容观测统计；**不得把旧 `qualityObserved` 改名为质量完成**。
- 已确认的字段修正不回写旧报告。若关闭新决策接入，未知仍不得触发补课或被重排理由包装成漏练。

## 4. 优化项 3：从“重新生成七日”升级为“最小必要调整”

### 4.1 当前问题

E06已经提供相同证据不重复写修订的保护，但证据变化后仍重构七日窗口。幂等与计划稳定性是两个问题。

当前未采集线上改课频率；“频繁变化”是待量化的风险，不在本文声称已发生。

### 4.2 目标

- 原安排仍可行时保留，只修补必要日期与新进入窗口的日期。
- 日期、课型、剂量变动为次级成本；硬约束永远优先。
- 每次变化记录原安排、新安排、证据、影响范围及安全降级标记。
- 同一证据不写新修订；不同证据但执行内容不变也不制造计划修订。
- 历史、已完成和锁定处方不被重写；当前不安全时可限制**有效执行层**，不能让锁定绕过安全。

### 4.3 建议方案

#### A. 硬约束与软目标

| 类型 | 内容 |
| --- | --- |
| 硬约束 | 生命周期、可跑步日、比赛日、自然周/滚动保护上限H、追加资格/次数、已完成量、窗口外保留量、质量上限、单堂≥30分钟及模板最低剂量、可用时长、轻松时长占比下限、长课上限、既有质量间隔、校准/分区资格、有效恢复/主观停止限制 |
| 常规规划目标 | 周建议量S决定常规课组合，不因达到S直接剪掉合法追加，也不以填满H为优化目标 |
| 存储保护 | 历史/已完成/锁定/迁移保护处方保持；无法安全执行时生成有效限制，不篡改原文 |
| 次级目标1 | 受约束闭包以外不改动已有执行内容 |
| 次级目标2 | 最少改变已有训练日期；移课计为一次移动，而不是新增训练机会 |
| 次级目标3 | 最少改变课型，再最小化工作剂量相对变化 |
| 次级目标4 | 在同成本下满足长课偏好和候选优先级，最终按日期、模板ID稳定排序 |

以上是字典序比较，不用一组可调权重让“少改课”抵消安全违反。所有候选先过硬约束才参与成本排序。

#### B. 受影响日期的计算

| 证据/配置改变 | 初始受影响集合 | 约束传播 |
| --- | --- | --- |
| 今日有效恢复或有效主观反馈 | 今天 | 联动自然周及滚动窗口余量、今日追加资格；不假装知道未来恢复 |
| 新训练/迟到记录导致预算或强度次数变化 | 涉及的未完成自然周 | 按实际训练更新周量/质量间隔；历史处方不变 |
| 模式/30分钟剂量版本激活；自动休息的预算/资格原因解除 | 不符合新合同的未来课；此前因已失效限制而自动休息的候选日 | 可重新选完整课；用户明确休息、暂停/结束、已完成和锁课不被自动升级 |
| 跑步日、每天时长、长课偏好改变 | 不再满足约束的未来日期 | 必要时扩展到相邻可用日；不补回过去训练 |
| 阶段/赛前保护切换 | 新规则下不可行的日期 | 同自然周及质量间隔相邻日期 |
| 分区或校准资格变化 | 目标或资格受影响的未执行课 | 剂量重新测量、预算联动 |
| 滚动窗口前进 | 新进入的一天、受跨周约束影响的日期 | 过去日期只退出窗口；已有重叠日期尽量保留 |
| 仅标签、解释文字、目标差距改变 | 无执行约束变化时为空 | 不因为“有新数据”重排整周 |
| S已完成而今日追加资格通过/失效 | 今天及有效执行授权 | 修补规则预算休息或限制未执行追加；联动滚动保护与预留，但不提前批准未来追加 |

闭包按自然周/滚动保护、预留与质量间隔依赖边扩展。**属于受影响窗口不等于必须修改整周**；七日以外处方作为固定约束参与校验，不静默扩大搜索/修改范围。只因达到S自动留下的休息不是用户休息意愿，今日追加通过时必须允许替换。

#### C. 确定性最小修改流程

```text
1. 在显式refresh命令中冻结事实、目标、策略版本；沿用CAS及operationId。
2. 固定历史、已完成、锁定及迁移保护的存储处方；计算其有效执行限制。
3. 验证已有重叠窗口，找出必须修补的初始日期和约束闭包。
   规则休息的原阻断已失效，且O0重新选择了明确可行训练意图时，将旧休息视为需修补；
   仅恢复变绿或预算增加本身不构成新增训练义务，用户明确休息仍保护。
4. 若原执行内容整体仍可行：
   保留已有日期；只补窗口新进入日，不因证据改变整体再生。
   第3步已判定意图失配的规则休息不属于“整体仍可行”。
5. 对闭包日期生成有界候选：
   原处方 / 同课型完整剂量变体 / 一堂规则替代课 / 完整轻松课 / 休息。
6. 用统一硬约束剪枝，在可行候选中按字典序成本选择。
7. 复核自然周和所有受影响滚动窗口，纳入已完成、受保护和窗口外保留处方及追加占用。
8. 经constrainUpcomingPlan及同一执行内容校验得到最终结果。
   若最后校验又改了内容，重新计算差异/成本/理由，不用校验前结果记账。
9. 执行结构及有效可执行/授权状态都不变：登记no_change评价收据，不提高goalsRevision。
   执行摘要改变：计划修订、变化记录、操作结果同控制库事务发布。
```

第一版最多每个日期5个候选，七日最多 `5^7=78,125` 个组合，按硬约束尽早剪枝；必须用固定排序保证确定性。这只承诺**有限候选集合内**最小成本，不宣称全训练空间全局最优。

- 需要移课时，原处方仅进入可用目标日期的“规则替代课”候选；只允许闭包内重新分配，不增加未完成训练的数量承诺。
- 为避免“全部休息最稳定”，休息不能替代一个仍可行的已有课而获得更低保留成本；新窗口日期再依据当前预算/候选选择。用户明确休息与规则自动休息保留不同来源：自动休息的阻断原因已解除时可纳入重新选择，否则最小修改会永久保留“预算不足”的旧休息日。
- 无安全可行解时，对可调整日期返回休息；受保护原文不动，有效执行标为受限，给出 `no_feasible_safe_plan`。
- 搜索超预算或失败时不得发布未校验候选。运行预算由O3-D实测后冻结；不在本文伪造耗时保证。

#### D. 变化日志与无变化收据

```ts
type CoachAdaptationRecord = {
  operationId: string;
  programmeId: string | null;
  scope: { serverId: string; athleteId: string; datasetEpoch: string };
  inputDigest: string;
  policyManifest: CoachPolicyManifest;
  evaluatedAt: string;
  sourceGoalsRevision: number;
  resultingGoalsRevision: number;  // no_change时相等
  result: "no_change" | "patched" | "safe_fallback";
  affectedDates: string[];
  changes: Array<{
    localDate: string;
    layer: "stored_plan" | "effective_execution";
    before: { kind: string; prescriptionDigest: string | null };
    after: { kind: string; prescriptionDigest: string | null };
    doseBefore: number | null;
    doseAfter: number | null;
    doseUnit: "work_seconds" | "work_meters" | "reps" | null;
    safetyDowngrade: boolean;
    reasons: DecisionReason[];
  }>;
};
```

- 记录中前/后摘要关联已有计划历史及确实使用的结构；不额外创建PlanRevision实体。
- 无变化收据建议以控制库的小型评价记录保存，唯一键含scope、programme、source revision、输入和策略hash；复用操作结果幂等。不得仅为更新 `adaptationKey/adaptedAt` 提高计划修订。
- 新事实令牌可能变化但执行摘要不变；二者不强行相等，现有执行租约保护仍保持。
- 同一30分钟结构由“待评估不可执行”变为“追加获准可执行”不是no_change：有效执行身份包含授权状态和决策引用，纳入同事务发布；不能只比较 `prescriptionDigest` 而漏掉资格变更。历史处方hash不因此改写。
- GET不登记评价；仅显式命令写收据。独立事实安全限制可以在既有只读有效处方装配中生效，不能为写日志让读接口变成写接口。
- 用户暂停/结束、实际少跑或未知记录，均不进入“欠课”字段；本方案不设置补课计数。

### 4.4 验收标准

| ID | 输入/边界 | 预期 |
| --- | --- | --- |
| AC3-01 | 同事实、同版本连续刷新/重启后重试 | 不增加计划revision，不重复操作或变化记录 |
| AC3-02 | 新证据但原安排仍满足全部约束 | 已有七日重叠内容不变；记录no_change |
| AC3-03 | 今天恢复限制命中，其他日期仍可行 | 必要降级及预算联动；无关联日期不改 |
| AC3-04 | 锁定今日质量课，安全限制随后命中 | 存储原文不改，有效执行降级或阻止；安全优先 |
| AC3-05 | 周日刷新跨至下周、窗口外有保留课 | 两自然周独立算账，不透支下一周或漏扣保留量 |
| AC3-06 | 过去质量课未观测/明确未完成 | 不新增补课债务，不把下一周挤成补课周 |
| AC3-07 | 等成本候选、多次重复运行 | 同样日期/课型/剂量和语义hash |
| AC3-08 | 并发目标修改、数据集更换、发布中故障 | 拒绝旧输入；失败不半发布，原指针/计划保持 |
| AC3-09 | 可枚举的小窗口与独立oracle比较 | 达到候选集合内最小字典序成本，不仅“比旧方案少改” |

关联回放：R01、R04、R06、R09、R10、R11。反向验证：锁定绕过安全、no_change提高revision、遗漏窗口外预算、补回未观测课，均必须失败。

### 4.5 风险与回滚

- 风险：保留旧课过多，阶段内容长期不更新；有限候选搜索影响延迟。
- 控制：阶段不相容的模板进入必须修补集合；测量搜索耗时及候选数，先离线回放。
- 回滚：版本化切回既有全量重建生成器，但仍经过同一硬约束、无补课规则和有效执行保护。
- 回滚不删除决策收据、不降低revision水位、不撤销已登记事实；需要重新发布课表时走新操作，设备更新继续由用户显式触发。

## 5. 优化项 4：让训练意图、距离和阶段决定内容，不只是限制跑量

### 5.1 当前问题

E07确认模板主要由预算/质量上限等驱动，质量候选固定为间歇和节奏，阶段主要约束量带及质量次数。

这是增强项，不表示现有模板失效。新增距离/阶段内容选择须建立在O0剂量与模式、O1语义统一及O2执行质量基础上。当前长课还存在复用最长easy结构后改kind的路径（E06），不足以证明已有真正的LSD剂量选择；法特莱克不存在独立语义（E16）。

### 5.2 目标

- 在现有生成和统一校验前增加小规模、版本化候选选择。
- 明确分开“为何选这堂课”和“为何裁成这个剂量”。
- 选择依据含模式、训练意图、距离、阶段、训练基础、近期执行评价；保护量H与安全限制保持硬约束，S只用于常规安排。
- 可用时长是安排输入，不进入能力基线；不恢复手填周跑量。
- 无比赛目标也可在资格满足时安排阈值、间歇、LSD或法特莱克，不将质量课专属于备赛模式；无须每周覆盖全部课型。

### 5.3 建议方案

#### A. 候选库及选择输出

```ts
type CoachTemplate = {

  libraryVersion: string;
```

分两步交付：O4-B/C先让已有轻松、恢复、长课结构、800m间歇及分段节奏构建器满足O0，并接入统一选择；O4-E/F补齐有氧/LSD的实质剂量政策和结构化法特莱克。**后一步是本次需求的必交付，不是“以后再说”**；具体组数、持续时间和资格审批前不得上线。阈值第一版可复用现有分段节奏结构，不强求连续阈值；比赛配速块仍不自动扩范围。

#### A.1 课名与训练语义映射

优先保留现有 `MobileSessionKind`，增加显式 `intent/templateId` 与刺激属性；不为中文显示名称建立多套枚举。共享HTTP合同、历史摘要及必要消费者协商后才启用，不能只在服务端私有模板中增加字段。

| 用户理解的课型 | 第一版执行映射 | 真正需要实现的差异 |
| --- | --- | --- |
| 休息 | `rest` | 无跑步结构，无30分钟义务 |
| 恢复/轻松跑 | `recovery/easy` + 相应intent | 低强度完整课，≥30分钟；不能仅因名称是恢复就低于下限 |
| 有氧跑 | `easy` + `aerobic_endurance` | 以有氧持续时间/工作量区别于较短轻松课；先用现有低强度目标，不凭名称捏造新Z3分区 |
| LSD/长距离慢跑 | `long_run` + `long_aerobic` | 基于个人长课历史和可用时间选择较长低强度课，保留单次/周占比上限；仅30分钟不自动称为LSD |
| 阈值训练 | `tempo` + `threshold` | 工作段取阈值目标；整课包括热身、恢复、整理；`tempo`在本库明确意图，不泛化所有“节奏” |
| 间歇 | `interval` + `interval` | 有限重复、明确工作/恢复段；遵守最低工作剂量、能力目标及间隔 |
| 法特莱克 | `interval` + `fartlek`（含高强度的模板） | 时间型快慢交替，不是800m间歇改标题；快/慢段分别定义目标和剂量，整课≥30分钟 |

- 含质量工作段的法特莱克必须占用质量课次数与间隔；不能因其“自由变速”名称算成全程easy。第一版只支持可解释、可测量的结构化变速模板，不自动安排无法核验剂量的开放式随机跑。
- 低强度时长占比按真实步骤目标/有效证据统计；不因 `kind=interval` 把热身全记高强度，也不能因 `kind=easy` 吞掉强段。长课即使低强度，也必须进入长课/总负荷约束。
- E16中 `workSecondsPerKm` 按整课kind选所有work配速，`runCoachSessionTargets`会统一重设work目标；对混合模板必须改为复用逐步骤语义测量/转换，快段和慢段在估量、警报、导出和刺激评价中一致，不能切心率偏好后全被覆盖成同一目标。
- 新语义参与 `prescriptionDigest`、事实/策略身份和执行评价；旧结构不重写hash。旧消费者无法理解新intent或步骤语义时，禁止导出该模板或给出明确的兼容替代，不能丢字段后悄悄换刺激。
- O2增加法特莱克评价：真实步骤不足时不确认完成；有氧/LSD参照对应连续/长课矩阵，但仍保留各自工作剂量与刺激意图。

#### B. 第一版候选优先表

表中是**通过资格/预算后**的候选优先级，不是每周必排承诺；可行的休息和轻松回退始终保留。

| 距离 | base | build | peak | taper / race_week |
| --- | --- | --- | --- | --- |
| 5K | 轻松为主，合格时已有节奏模板 | 优先已有间歇模板 | 合格且相容时保留间歇，不能越过赛前保护 | 仅允许满足保护及既有剂量政策的候选 |
| 10K | 轻松及合格节奏 | 优先节奏，预算/间隔允许时才考虑间歇 | 保留已验证的节奏候选 | 同上，不新造“短促刺激”剂量 |
| 半马 | 轻松与有历史支持的长课 | 优先长课/节奏；间歇不是默认第一候选 | 保留专项耐力内容，不因单次成功加量 | 同上，不用减量阶段补长课 |
| 无比赛持续训练 | 不适用比赛阶段；低强度为基础，合格时按近期刺激选阈值/间歇/法特莱克，历史支持时选长课 | `phase=null` | 不伪造peak | 不产生无赛事的赛前保护 |
| 有比赛但距离无骨架 | 沿用兼容模板及新整课约束，`phase=null` | 不伪造阶段 | 不宣称已支持该距离专项周期 | 仅既有兼容保护 |

选择器顺序：模式/资格过滤 → 近期刺激与阶段/距离相容 → 整课剂量及预算可行性 → 已有课保留成本 → 同类执行证据 → 上表优先级 → 模板ID固定排序。阈值、间歇、法特莱克通常是质量候选间的选择，不因课型多就增加每周质量次数。

- 校准未完成只允许既有保守轻松训练。
- 近期已知未满足同类质量课时，优先较低剂量变体/轻松回退；证据未知不等于失败。
- 单次确认完成不自动升级难度；升级只走已审批的训练基础和剂量政策。
- 无赛事的近期刺激轮换只在当前没有适合保留的课、阶段/资格变化或需要修补时参与选择；不能为“多样性”每天换掉仍然合适的已发布课。也不能因久未做质量课而自动增加组数；现有 `intervalReps` 的随间隔加组策略须在O4-A显式审查并替换为有训练基础支持的有限剂量等级。
- 目标时间不是候选强度来源。课表目标继续来自能力/分区，不能为了追目标配速突破当前强度限制。
- 进入超S追加分支时先应用§1.7白名单：首版仅30分钟低强度课；本节的阈值/间歇/法特莱克/LSD优先级不能覆盖追加限制。用户目标或“缺专项刺激”也不能成为超S加质量课的理由。

#### C. 选择器、裁剪器、校验器分工

```text
事实与阶段 → 选择器：过滤及排序候选，给出选择证据
                  ↓
既有结构构建器 → 剂量裁剪器：工作量/时长/组数有限变体
                  ↓
constrainUpcomingPlan + validateWeeklyPlan：全周与单堂硬约束
                  ↓
最终结构实测 → 复核课型语义、回退链及摘要
```

裁剪后已不足以表达原训练意图时，沿 `permittedFallbackIds`换模板并记理由，不能只改距离数字而保留原组数或虚假课名。原模板降成轻松课时，原选择与最终课型均需可追踪。

#### D. 每天可用时长

- 建议新增可选 `availabilityMinutesByWeekday`，键为1–7，值为整数分钟或 `null`。
- 第一版输入范围10–240分钟作为协议限制，超范围拒绝而非钳制；具体范围在O4-A冻结，属于工程初值。接受10–29分钟仅表达真实时间约束，不代表允许自动跑课低于30分钟；按O0输出休息及原因。
- 未设置表示没有用户时长约束，不等于有无限训练容量；是否可跑仍由既有 `runningDays`决定。
- 全课时长包含热身、工作、恢复和整理。可靠估计的区间上界须不超过用户可用时长。
- 无可靠时长估计时不能声称“已满足时间约束”；选择可表达的时间结构或安全回退，不用显示时长代替结构时长。
- 时长变化只影响未来安排及最小修补闭包，不能改CA/TA、近期实测周量或能力基线。

## 6. 优化项 5：补上低摩擦的主观反馈

### 6.1 当前问题

E08已有训练后RPE及负荷使用。恢复输入主要是睡眠、HRV、静息心率；独立的训练前疲劳/酸痛/不适及中断原因闭环属于**建议新增能力**。

不把反馈缺失当作当前系统故障，也不把现有RPE再实现一套。

### 6.2 目标

- 训练前可跳过，训练后复用RPE，只补原因。
- 自述与设备证据并列，保留来源、发生/录入时间与有效期。
- 今日补录的昨日感受不能出现在昨日 `as_known_then`决策中。
- 新自述只影响安排，不直接或通过改写课型间接污染CA/TA。

### 6.3 建议方案

#### A. 字段与存储职责

```ts
type SubjectiveFeedback = {
  id: string;
  revision: number;
  scope: { athleteId: string; datasetEpoch: string };
  localDate: string;
  phase: "pre_run" | "post_run";
  workoutId: string | null;
  fatigue: "usual" | "elevated" | "high" | null;
  soreness: "none" | "mild" | "marked" | null;
  discomfort: "none" | "present" | null;
  requestedAction: "none" | "easy_only" | "rest" | null;
  interruptionReason:
    | "time_constraint" | "fatigue" | "discomfort"
    | "weather" | "equipment" | "other" | null;
  replacementReason:
    | "time_constraint" | "preference" | "fatigue" | "discomfort" | "other" | null;
  rpeOverrideRef: { workoutId: string; revision: number } | null;
  observedAt: string;
  recordedAt: string;               // 服务端持久化时刻
  availableAt: string;              // 不早于服务端首次保存
  validUntil: string;               // 服务端按版本化有效期计算
  retractedAt: string | null;
};
```

- 全部主观项目可为null；跳过不生成“正常”记录，不降低覆盖或资格。
- `pre_run`不接受workoutId/RPE关联；`post_run`要求真实workoutId，且属于当前数据域。
- RPE仍由既有override命令保存、验证和计算；这里只关联其修订，**不存第二份RPE值**。
- 新增事实建议保存在主健康库的追加修订表，走既有单写者/命令机制，纳入备份、删除和数据集恢复；不能仅存在控制库导致健康事实备份遗漏。
- 不改已有RPE对负荷的作用。新字段不能进入Fitness特征、评分学习率、训练类型override或置信度惩罚。
- 修改/撤回生成新修订或墓碑，保留旧时点证据；不物理覆盖历史行。

#### B. 时间语义与作用范围

第一版有效期政策：训练前状态从 `observedAt` 起，至该状态发生日的下一个上海本地午夜；跨日不自动延续。训练后原因用于该训练解释，不自动变成第二天恢复状态。

```text
可参与asOf决策必须同时满足：
observedAt <= asOf
availableAt <= asOf
asOf < validUntil
该反馈修订在asOf时未撤回
数据域身份正确
```

- 昨日感受今天录入可用于历史复盘，但不能改变昨天已经发布的决策，也不能自动成为今天的训练前状态。
- `observedAt`不能是未来时间；`localDate`按固定业务时区派生，不能信任客户端随意提交的日期。
- 连续不利反馈仅统计各日当时有效且已可得的记录；缺一天不填前一天值。
- 有效期结束是证据过期，不是系统确认恢复。明确用户休息要求只作用于本次有效日期，不隐式延长计划暂停状态。

#### C. 第一版安排规则

| 触发 | 作用范围 | 安排行为 | 不允许 |
| --- | --- | --- | --- |
| 有效 `requestedAction=rest` | 今天 | 有效处方休息；保留原锁定/历史文本 | 用设备好状态升级为质量课 |
| 有效 `requestedAction=easy_only` | 今天 | 禁止质量课，不抬高预算 | 将“愿意轻松跑”当长期能力下降 |
| 有效不适，或高疲劳与明显酸痛同时存在 | 今天 | 阻止新增质量课；复用既有安全降阶，说明来自自述 | 诊断受伤，生成疾病名称 |
| 疲劳升高但无停止请求/其他不利证据 | 今天 | 记录证据；按已审批联合规则决定，不凭单字段必然休息 | 伪造精确恢复分数 |
| 训练后因时间/天气/设备提前结束 | 当前训练评价 | 保留实际剂量及原因，不自动推断生理疲劳 | 为完成率提高翌日训练量 |
| 训练后因疲劳/不适结束或替换 | 当前训练及可解释趋势 | 附已知原因；下一次决策需有效新证据或审批的趋势规则 | 将原因无限期当恢复闸门 |

自述与设备意见相反时仍并列返回；明确休息/轻松请求不能被设备读数覆盖。其他自述规则须版本化评审，不修改E08的设备恢复计算。

协议解释只需返回两组独立证据及原因，如“设备恢复证据未发现低信号；你报告今日疲劳高，今天不追加质量课。”不定义页面布局。

#### D. 写入与任务拆分

- 建议新增主观反馈命令，复用已有命令幂等、expectedRevision及mutation协调；不把健康事实写入伪装为goals写入。
- 反馈保存成功与后续分析/计划刷新成功分开；重试不得因刷新失败重复录入。
- 反馈revision/hash进入事实快照、适应输入和回放；GET读取不触发自动刷新或后台排课。

| --- | --- | --- |
| O5-A | 自述合同、有效期、安排规则、RPE引用及撤回语义审批 | O3、E08 |
| O5-B | 主库追加事实/命令/查询；新增migration及冻结值，不修改旧migration | O5-A |

## 7. 优化项 6：增加“目标差距”，继续避免“达标概率”

### 7.1 当前问题

E09确认准备度语义正确，尚未将目标时间与成绩参考接通。缺口是轻量预测摘要及一致读取，不是重新设计预测模型。

本项是新能力；不声称已能判断目标一定可达或不可达。

### 7.2 目标

- 既有异步预测链产出摘要，教练同步读取，不在GET调用报告构建器。
- 分开返回能力参考、目标秒数差、专项缺口、新鲜度和校准状态。
- 未校准仅提供参考/限制说明；不输出百分比成功率。
- 激进目标只触发解释与修改建议，不抬高预算、质量次数或区间。

### 7.3 建议方案

#### A. 轻量摘要与情景

```ts
type CoachPredictionSummary = {
  schemaVersion: number;
  summaryId: string;
  sourceBundleId: string;
  sourceBundleHash: string;
  datasetEpoch: string;
  factsHash: string;
  overrideHash: string;
  labelCohortHash: string | null;
  activePredictionArtifactId: string | null;
  predictionPolicyVersion: string;
  scenario: "current_prepared";     // 沿用既有情景枚举，不混用理想潜能或假定比赛日恢复
  asOf: string;
  publishedAt: string;
  dataThroughAt: string | null;
  availableAt: string;
  entries: Array<{
    distance: "five_k" | "ten_k" | "half_marathon";
    status: "available" | "insufficient_data";
    referenceSeconds: number | null;
    method: string;
    calibrationStatus: "uncalibrated" | "personal_reference" | "empirically_evaluated";
    range: { lowerSeconds: number; upperSeconds: number;
      kind: "heuristic_not_calibrated" | "personal_reference" | "empirical" } | null;
    evidenceRefs: EvidenceRef[];
    limitationCodes: string[];
  }>;
};

type CoachGoalGap = {
  status: "available" | "no_time_goal" | "unsupported_distance" |
    "summary_unavailable" | "stale" | "incompatible";
  summaryId: string | null;
  distance: "five_k" | "ten_k" | "half_marathon" | null;
  targetSeconds: number | null;
  referenceSeconds: number | null;
  gapSeconds: number | null;
  preparationGaps: Array<{ code: string; evidenceRefs: EvidenceRef[] }>;
  freshness: { asOf: string | null; dataThroughAt: string | null; stale: boolean };
  calibrationStatus: string | null;
  reasons: DecisionReason[];
};
```

`gapSeconds = referenceSeconds - targetSeconds`：

- 正值表示参考时间比目标慢，如参考50分钟、目标45分钟，差距为 `+300秒`。
- 负值表示参考时间比目标快，但不保证达标。
- 只计算秒数及可选秒/公里差，不换算成成功率或“达标信心”。
- 当前准备情景使用既有 `current_prepared`预测方式；不把 `neutral_potential`的理想准备值当现实差距，不擅自假定未来恢复/天气。
- 现有 `confidence`、准备度百分数不映射成目标成功率；本文新对象不增加probability字段。

#### B. 生成、发布与失效

1. 在既有异步预测任务完成时，从同一次结果提取摘要；不重复执行报告/ONNX推理。
2. 使用主库的小型不可变摘要工件及其可兼容发布指针；建议 `coach_prediction_summaries`，不是完整计划实体。
3. **不要向已封存的E12领域快照补写新domain**：其hash及完整bundle已冻结。摘要作为伴随工件，绑定既有bundle、事实及预测工件身份。
4. 重计算在事务外执行；最终通过既有mutation/publication协调，在写事务内复核bundle、事实、override、标签和活跃预测工件未变后登记。
5. 同摘要hash幂等；失败不改变兼容incumbent指针，不半发布。若incumbent已经不兼容，则只读结果为 `incompatible`，不能继续当当前参考。
6. 数据集恢复、训练/override变更、标签撤回或预测模型激活/回滚，使原摘要重新核验或失效；相同源码版本不是充分兼容条件。
7. 刷新在既有明确的计算/发布任务流程触发；读接口不排队计算、不写状态。缺摘要返回原因，不临时现场构建。
8. 摘要计算失败不阻断核心评分或安全安排；这是可缺失的参考输出，不降低原预测/ML发布门槛。

第一版新鲜度工程政策建议：`dataThroughAt`距当前业务日期超过7天即 `stale`；null为证据不足；`asOf`和 `dataThroughAt`分别返回，不能用刚计算的时间掩盖旧训练。7天不是准确性保证，须在O6-A冻结并覆盖6/7/8天边界。

#### C. 教练读取与目标提示

- 在既有 `training-plan-state.coachSummary`内增量返回 `goalGap`，同步读摘要及准备度；身份纳入同一冻结视图及令牌。
- 独立run-coach兼容读取复用同一装配函数；没有摘要时不触发昂贵构建。
- 无时间目标为 `no_time_goal`，自定义/全马为 `unsupported_distance`，不外推预测。
- 新鲜且兼容参考比目标慢时，返回事实性提示：“当前参考比目标慢X秒，可考虑调整目标或重新评估准备期。”
- 是否“大幅差距”第一版不增加未经验证的分档，只报告差值；不把任意百分比阈值称为不可达。
- 修改目标沿用原有目标CAS规则，不自动更改固定赛事日期；需要更换赛事继续创建新计划。
- 目标差距和准备度缺口不进入周容量提升或质量加课规则。

## 8. 优化项 8：把“教练行为回放”作为每项优化的验收基础

### 8.1 当前问题

E10已有算法回放、可得时间和版本发布基础；仍需面向教练行为的跨周场景、变化指标及发布判据。这是新增覆盖，不声称当前没有测试。

### 8.2 目标

每项优化至少对应一个固定场景和反向验证。测量改课次数/幅度、实际质量刺激间隔、未知误判、解释覆盖和处方保护；证明行为可靠性，**不以合成通过证明训练效果**。

### 8.3 建议方案

#### A. 场景结构与执行器

```ts

  version: string;
  timezone: "Asia/Shanghai";

  initialStateHash: string;
  replayMode: "as_known_then" | "event_time_reconstruction";
  events: Array<{

      "zone_change" | "lifecycle" | "publication" | "refresh";

    payloadHash: string;
```

- 复用 `ReplayDescriptorV2/replayModelPair`，新增跨事件适配器而非独立模拟训练引擎。
- 每个事件只在 `observedAt<=asOf && availableAt<=asOf`时可见；迟到事实不能提前进入。
- 原始可得时刻未知时，只能标 `event_time_reconstruction`，不能认证真实历史当时可知。
- 同输入运行两次，语义结果必须一致；输入不可变，策略版本明确。
- 旧新方案在同一初始状态和**同一外生事件流**上比较；不因为候选课表不同就虚构用户执行或训练效果。
- 评估者掌握标签/预期，不将未来测试成绩作为教练输入；合成输入不包含真实路线、凭证或健康原库。

- AC8-02：核心跨周场景完整执行事件流，输出变化数/范围/剂量与未知覆盖。
- AC8-03：同输入两次语义一致；asOf之后的事件/标签不得进入。
- AC8-04：硬门槛全为0；观察指标有明确分母和基线，未测项为 `not_evaluable`。
- AC8-05：O0/O1/O2/O3/O4/O5/O6指定语义突变均先成功编译，再被对应行为断言拒绝；编译失败不算有效反向验证。
- AC8-06：评估产物明确“行为可靠性”，不报告未经真实标签和长期观察支持的训练收益。

### 8.5 风险与回滚

- 风险：场景膨胀、golden跟随错误实现更新、测试只验证格式。
- 控制：核心场景固定；新增场景必须对应真实风险；golden变更需解释行为差异并由非实现作者复核。
- 回滚：可回退场景适配器版本，保留旧产物；安全、时间泄漏和未知误判等核心门槛不可通过关闭场景绕过。
