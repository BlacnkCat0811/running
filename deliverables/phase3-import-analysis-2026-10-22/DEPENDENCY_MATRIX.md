## 0. 读法与边界

1. 本矩阵区分两个问题（方案 §5 末段）：
   - **需要哪些历史输入**（下表"实际读表/回看窗口"）；
   - **哪些历史输出可复用**（下表"复用证明"）。
   后缀重算仍可能需要较长回看历史；`apps/.../analysis-input-reader.ts:716-721` 使用各域边界的**共享最大回看窗口** `RECORDS_MAX_LOOKBACK_MS`（`analysis-fact-view.ts:205` = 365+180 天）裁剪输入，不得用更短的 dirty 窗口截断输入。
2. 分析入口的脏范围由 `planIncrementalAnalysisDirtyRange`（`packages/health-export-parser/src/dirty-range.ts:180`）给出；它返回 `domains.features / domains.fitness / domains.readiness`（`dirty-range.ts:303-307`）。注意当前实现里 `domains.fitness === domains.readiness`（同一个 recovery 边界），**不存在独立的 readiness 增量链**；`domains.readiness` 只用于读侧/裁剪，`resolveMetricReuse` 读的是 `domains.fitness`（`recompute-pipeline.ts:2497-2499`）。
3. 全量/拒绝复用的消费侧入口与计数：`RecomputePipeline.replayTrainingMetrics`（`recompute-pipeline.ts:2671`）→ `resolveMetricReuse`（`:2491`）→ `replayTrainingMetricsFull`（`:2723`，`reused=0`）或 `replayTrainingMetricsReused`（`:2771`）。计数落在 `training_metric_runs.summary_json.reuse`（接口 `MetricReuseCounters`，`:364-378`）。能力时间线复用计数落在 `model_runs.reused_assessment_count`（`resumeModelReplay`，`:3667`）。

## 3. 派生身份 D1（已修复并改为原始值比较）

- **原现象**：同一份事实、同一父发布下，增量 A 与离线全量 B 的 **raw** `baselineEpochId` / `calibrationCohortHash` 不一致；增量得到空校准集 hash，全量得到 15 场训练。
- **根因**：`fitnessEpochId` / `calibrationCohortHash` 用 `baseline.calibrationFeatureIds.includes(feature.id)` 过滤**当前 run** 的 features；`resumeModelReplay` 把父 checkpoint 的 baseline 原样带回，而它保存的是父 run 的 feature id；`copyFeaturePrefix` 给复用行生成当前 run 的新 id。
- **修复（2026-10-22 复审后）**：`remapResumedCheckpointState()` 按稳定 `trainingSessionId` 把父 checkpoint 的 `calibrationFeatureIds`（及 `pendingNegativeIds`）映射到当前 feature run，并校验数量、唯一性、可解析性、校准区间、dimensions、顺序和 `throughSequence` 边界；复制 checkpoint 时写入重映射后的 `state_json` 与 `state_hash`。任一不一致 ⇒ 拒绝复用并安全全量，旧 checkpoint 仍可读、不批量改写历史。
- **比较口径**：`business-artifact-projection.ts` 已删除 `replaceDerivedHashes` 语义替换；lineage、daily snapshot、assessment explanation、五域封存 payload 中的 `baselineEpochId` / `calibrationCohortHash` **全部比较原始持久值**，`lineage_hash` 仍逐 run 自证。负对照证明篡改任一 raw hash 会让比较器失败。
- **证据**：`P3-06_EVIDENCE` 的 `route_move_xml_only` 等场景；`training-metric-domain-reuse.test.ts` 的连续两轮增量 epoch 稳定用例与损坏父校准 cohort 拒绝用例；`phase3-business-artifact-differential.test.ts` 的 raw hash 负对照。
