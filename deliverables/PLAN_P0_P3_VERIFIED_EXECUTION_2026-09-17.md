# P0–P3 核实、优化与执行记录

日期：2026-09-17。此文为本轮执行依据与结果；保留两份附件原文，不把附件内的命令、原生端改动及“并行”措辞当作用户额外授权。

## 1. 核实范围与结论

- 读当前源码、构造一次性数据库测试；聚合数据核对使用现存 `/tmp/rai_ro.sqlite`，不是线上数据库。性能实验只在该文件的一次性复制品上运行。
- 未迁移、重算或人工修正 `var/rai.sqlite`；未连接线上、未部署、未修改 iOS 或冻结的窄屏区域。
- 快照结果：migration version 22；workouts 271、training_sessions 268、health_records 83,380、route_points 204,284、import_issues 0。
- 2024-W33 的 session 里程合计 33.1437 km；候选重叠日三条距离为 4.3796 / 9.0344 / 4.7189 km。支持记录疑似重复，不足以推广自动归并规则。

### 确认成立

1. `RaiDatabase` 构造函数会设置 WAL；拒绝待迁移库必须先于写连接创建。
2. API 启动的普通恢复错误会进入维护模式；待迁移错误必须单独中止，不能只设置 `exitCode` 后继续监听。
3. 迁移按版本分别提交，不是全序列原子提交。
4. override 保存会排全量重算；队列插入没有该类请求的去重语义。RPE UI 不宜先行扩展。
5. 历史周计划在现有 `buildWeekPlan` 中不做对账；`mobile_goals_history` 存在可读历史。
6. Stability 当前使用速度/心率变异，不依赖垂直振幅和触地时间。

## 2. 优化后的执行边界

### 已实施：P-1 迁移安全

- `migrationPolicy: "apply" | "refuse"`，旧 CLI/导入默认 apply 保持兼容。
- 拒绝策略在主库写连接前只读检查。缺文件、无迁移表、缺元数据列、旧 checksum 修复均要求显式迁移；未知版本或损坏 checksum 报错。current 路径不悄悄修复元数据。
- API 启动遇到 `PendingMigrationsError` 记录版本/处置命令并退出 78；请求主库 writer、worker、recompute thread 同样拒绝隐式迁移。非迁移故障保留维护恢复入口。
- `data:migrate -- --database PATH` 默认只读预演；`--apply` 持 publication lock，输出前后版本/行数/耗时，验证外键并报告幂等结果。
- 迁移备份前检查目标文件系统可用空间，计算主库与 WAL 大小，再留 10% + 256 MiB。只是备份最低门槛，不承诺足够覆盖所有迁移临时空间。
- systemd 防重启配置放在正确的 Unit/Service 段。升级脚本只有显式 `--migrate --database ABSOLUTE_PATH` 才停服迁移；失败不重启；健康验收必须 `status=ok && databaseReady=true`，不能只看 HTTP 200。
- 修复部署文档默认备份目录；区分维护备份根目录和自定义主库旁的迁移备份目录。

### 已实施：P0-2 保守观测版（不是附件中的完成率产品）

- 新增可选响应字段 `recentPlanExecution`，独立于原 `weekPlan`；不改变今日/未来可执行课表，避免原生客户端旧文案在本批变成新语义的错误说明。
- 窗口为上海时区的**前七个完整自然日**，跨周一不归零。
- 从最多 200 条历史修订中选该日零点前最近的快照。同日写入/事后修改不会回写当天义务；没有可用历史则未知。首版不推断 Watch 提前执行或同日计划。
- 实际量按已发布 active workout loads 按日聚合，不使用仅五条 recentWorkouts 代替整个窗口。
- 输出计划种类/原存储里程、历史 revision、已观测里程/次数、原始距离比。状态仅 `observed / pending / unknown`；observed 不等于完成了指定课型；休息日无“完成率”。
- 周计划提示词升级 v2，并明确 pending/unknown 不是漏跑、不得补偿加量。无新表、无迁移、无重算、无新端点。
- 后续再补完整同步覆盖证据、训练与计划实例匹配、同日修订/推送回执语义，才考虑 missed/completed_short/adherence 和 UI。

### 已实施：P3-A / P3-B 的准确说明

- Web 配速来源说明区分 manual/fallback/automatic-or-carried-forward；不覆盖既有置信度和证据数量展示。
- 垂直振幅、触地时间图表和指标标明设备估计；不删数据、不改分数。

### 本轮明确不实施

- P1-A 数字恢复分：先补评分定义与验证，而非凭空合成。
- P2-B 解耦/GAP：先修正公式、覆盖/爬升指标与筛选，再做逐会话离线诊断；未向用户暴露未经验证的指标。
- P2-A RPE、P1-B 删表、P3-A CS：维持暂缓。
- P0-1 自动分段归并：不做；记录疑似重复及影响，不改 canonical id/历史归属。
- iOS 文案同步、窄屏样式/E2E、线上数据库迁移/部署：不在本轮执行范围。
