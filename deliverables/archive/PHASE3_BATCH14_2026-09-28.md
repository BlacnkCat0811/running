## 0. 结论

§10.4 的 `ZoneCoherence` 落地，并且**把原文那句禁令写成了可执行的映射表**：

> 注意 HR zone 和 Pace zone 的类别并不完全同构，**不能把各自数组下标相减当"冲突分"**。

- 新增 `assessZoneCoherence()`：两侧先映射到**共享生理努力档**，再用**显式语义映射**判断对齐；
- 新增 `ZoneCoherence`（契约层类型）+ `WorkoutZoneSummary.zoneCoherence`（**可选字段**，见 §2.4）；
- **`pairedCoverage` 是真实配对**（两条时间线按边界扫一遍），**不是** `min(两侧覆盖率)`；
- `sustainedConflictSeconds` 只计**达到最小持续时长**的分歧 ⇒ 间歇期的 HR 滞后不会变成常态冲突（§10.4 明确要求）。

**并且给出了那个缺陷的可复现反例**（本批最重要的产出）：

| 情形 | 旧判据（下标相减 `≥2`） | 语义判据 |
|---|---|---|
| HR `aerobic_base`(idx 1) + Pace `lactate_threshold`(idx 2) | `\|1−2\|=1` ⇒ **判为一致** | **`pace_high`（持续冲突）** |

心率是轻松档而配速是阈值档 —— 心率漂移或传感器问题的经典信号，**旧判据直接漏掉**。
这不是理论推演，是断言里跑出来的（见 §3.1）。

### ⚠️ 但旧的判据**没有切换**

旧的 `conflict` 仍在跑，并且喂 `stimulusConfidence`（冲突时 −0.2）与 `explanationCodes`。
切它**会改变对外数值**，所以按 §9.5 第 5 条的路径：**先迁移（本批），再离线比较（下一批）**。
两个判据现在并存，`zoneCoherence` 让那次比较有据可依。

## 2. 关键设计选择

### 2.1 "不得下标相减"落成一张**显式表**

```ts
const heartZoneEffort: Record<HeartRateZone, number> = { recovery: 0, aerobic_base: 1, aerobic_power: 2, lactate_threshold: 3, anaerobic: 5 };
const paceZoneEffort:  Record<PaceZone,     number> = { easy: 0, marathon: 2, lactate_threshold: 3, anaerobic_endurance: 4, sprint: 5 };
const acceptedPaceEffortForHeartZone: Record<HeartRateZone, readonly number[]> = { ... };
```

`aerobic_power` 只在 HR 一侧、`anaerobic_endurance`/`sprint` 只在 Pace 一侧 ——
**两套阶梯的档位数与含义都不同**，所以"对齐"只能由**语义表**回答。
表里把 `aerobic_base` 的可接受 Pace 档写成 `[0, 2]`（easy 或 marathon）而不是 `[1]`，
是因为 Pace 一侧**没有**对应 `aerobic_base` 的这一档 —— 这正是不同构之处。

### 2.2 `pairedCoverage` 必须是**真实配对**

拿 `min(心率覆盖, 配速覆盖)` 是最容易犯的错：两条线各覆盖一半但**互不重叠**时，
`min` 会给出 0.5 并通过门槛，报告一个"两个从未同时出现的来源之间的一致性"。

本版把两条时间线按边界扫一遍，只累计**两侧同时落到某个分区**的时长。
断言里专门造了这个反例（前半程只有心率、后半程只有配速 ⇒ 配对率 **0**）。

### 2.3 "持续"是必要的，因为 HR 有滞后

§10.4 明写"间歇中的 HR 响应滞后不应成为常态冲突"。所以：
分歧只有**连续达到 `minimumSustainedSeconds`（默认 90s）**才计入 `sustainedConflictSeconds`。
断言覆盖两侧：30s 的分歧 ⇒ `aligned`；180s 的同类分歧 ⇒ 计入 180s 并给方向。

### 2.4 `zoneCoherence` 是**可选**字段，并且写明"缺失 ≠ aligned"

`active_workout_zone_summaries` 是**按列存取**的（不是整块 JSON），落这个字段需要**新增列** ⇒ 属迁移量级，
§14 的迁移归 Phase 5。本批不夹带迁移，所以：

- **内存计算路径**（`analyzeWorkoutZones`）总会给出它；
- **从库里重建**的 summary 取不到 ⇒ 契约里标为可选，并写明
  **消费方必须把"缺失"当作"未计算"，不能当作 `aligned`**。

这与 §5.3「缺数据不得谎报已归一化」、§8.3「未校准不得给分数」同一条原则：
**不知道 ≠ 没问题。**

## 3. 验收证据

### 3.1 五条断言

1. **语义 vs 下标**：HR `aerobic_base` + Pace `lactate_threshold` ⇒ 旧判据 `false`（一致）、
   本实现 `pace_high` + 1200s 冲突 + 原因码 `pace_leads_hr`。**这就是 §10.4 那句话的反例。**
2. **同名档必须对齐**：HR `lactate_threshold`(idx 3) 与 Pace `lactate_threshold`(idx 2)
   下标差 1 ⇒ 旧判据 `false`；语义上二者**同义**，本实现 `aligned` 且 0 冲突秒。
3. **真实配对**：两半互不重叠 ⇒ `pairedCoverage = 0` + `insufficient`；
   真实重叠一半 ⇒ `0.5` + `aligned`。
4. **持续才算冲突**：30s ⇒ `aligned`；180s ⇒ `sustainedConflictSeconds = 180` + `pace_high`。
5. **配置校验**：越界的 `minimumPairedCoverage` / 负的 `minimumSustainedSeconds` / 负容差 ⇒ 抛错。
