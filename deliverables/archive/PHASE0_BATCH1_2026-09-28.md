## 2. 关键设计选择（存在多方案时）

### 2.1 为什么 `canonicalSemanticJson` 对 NaN **抛错**，而不是写成 `null`

三个候选：(a) 学 `JSON.stringify` 静默写 `null`；(b) 写成 `null` 并在报告里标注；(c) 抛错。

**选 (c)。** 依据不是通用最佳实践，而是本项目吃过的一次真实亏：`JSON.stringify` 会把
`NaN`/`Infinity` 静默改写成 `null`，导致"在打印出来的 JSON 上断言没有 NaN"是**假断言** ——
把 `NaN` 注入报告后那条子进程断言依然全绿。既然语义哈希的用途正是"证明两次运行结果相同"，
一个会把差异抹平的序列化器会让哈希**看起来稳定而实际已经失真**，那正是要防的东西。
选 (a)/(b) 等于把同一个坑再挖一遍。

配套约束：非有限数、`Date`/`Map`/类实例/函数一律拒绝（(a) 会把 `Date` 降级成 `{}`、
把函数整条丢掉）。允许的只有明文：plain object、array、string、有限 number、boolean、null。

### 2.2 为什么 gate v2 **本批不落库**

`model_validation_gates.status` 有硬约束
`CHECK (status IN ('passed','failed','skipped'))`（`database.ts:1320`），而本 gate 的结果域多出
`not_evaluable`。三条路：

1. 把 `not_evaluable` 存成 `'skipped'` —— **否决**。该表 `skipped` 的既有语义是"没有 base 可比较"，
   混用会让审计分不清"没比"和"比不了"，而这恰是 §14.5 第 6 条点名要禁止的"自动当作通过"。
2. 在 `'failed'` 里塞 `not_evaluable` 理由 —— **否决**。会把"证据不足"谎报成"验证不通过"。
3. 本批只交付**纯决策函数 + 断言，不落库** —— **采用**。

第 3 条同时满足两个硬约束：§14.8 禁止改 v1–v22 历史迁移，而放宽该 CHECK 必须重建表，
属于 §17.7 PR 03 的"最小迁移"职责，不应提前塞进 Phase 0。

> ⚠️ **诚实边界**：本批交付的是"门禁的实现 + 验收断言"，**不是**已经生效的运行门禁。
> 它尚未接入 `recompute-pipeline`，因此公告上**不能**说"发布已被 v2 gate 保护"。
> 接入与落库随 PR 03 的迁移一并完成。

### 2.3 为什么跨标尺只豁免"分布连续性"，而不是放行一切

按 §14.5，同标尺（feature schema + model version 均未变）继续执行**全部**旧阈值；
跨标尺时仅把"已删除维度的分布连续性"降级为**记录项**（进入 `migrationReport`），
其余硬失败一律保留：

- `invalidValueCount > 0`、任何指标非有限 → 两种标尺都失败；
- `eligibleSessionDelta`、`assessmentStatusChangeRate` → 两种标尺都失败；
- 跨标尺时，改用两条**替换断言**：F01 恢复隔离必须成立、Readiness 输出覆盖必须满。

替换断言的三个分支被刻意分开，避免"缺证据"被当成"通过"或"失败"：
`null`（未运行）→ `not_evaluable`；`false` → `failed`；未达标 → `failed`。

`status` 无法判定（版本缺失）时判 `not_evaluable` 而非任选一侧 —— 宁可报"比不了"，
不可按错误的一套断言放行。同时暴露 `blocksActivation`（`status !== "passed"`），
要求消费方读它而不是判 `status === "failed"`，否则 `not_evaluable` 会静默发布。

### 2.4 为什么 re-export 放在 `contracts/src/index.ts` 的**文件末尾**

首版把 `export * from "./semantic-json.js"` 插在第 7 行，结果该文件整体下移一行，
`npm run check:doc-refs` 立刻报出 `contracts/src/index.ts:8 / :132 / :287 / :676-685`
四处"锚在空行"——既有交付文档 `ARCHITECTURE_PRODUCT_STATUS_2026-09-28.md` 的行号引用被顶偏。

这不是假警报，是真实回归，且**越界检查不会发现**（四处都没越界）。改为文件末尾追加后，
1–1158 行编号完全不变，四处告警归零（全仓"锚在空行"由 11 处回落到 7 处，其余 7 处与本批无关）。
代码注释里已写明这个约束，避免下次有人把它挪回顶部。
