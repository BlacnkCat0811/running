## 2. 关键设计选择

### 2.1 为什么 `evidenceReliability` **不落库**

§6.7 要求因子缺失时 `evidenceReliability = null`，但 **`ability_assessments.confidence` 是 `REAL NOT NULL`**。
要存 null 就得改列 ⇒ 迁移 ⇒ 属 Phase 5 的职责，不该塞进本批。

所以本批把它作为**决策输入**新增，**不新增列**。可审计性没有丢：原始三因子本来就已经落在
`confidence_factors_json` 里，**E 可以由持久化数据复算**，不需要再存一份。

### 2.2 为什么 `dataConfidence` 直接用既有 `qualityScore`，而 `source` 不再单独加权

文档说"把原 coverage/source 权重归入 data 一项"且"信号覆盖和设备来源**只能计入一次**"。
而 `qualityScore` 本来就是 `0.55×coverage + 0.25×sourceConfidence + 0.2×eligible` ——
**它就是现成的 dataConfidence**。旧的四因子算法把 `source` 又单独算了一份，正是"同一信号计两次"。

因此：`E = exp(0.60·ln(qualityScore) + 0.25·ln(comparability) + 0.15·ln(maturity))`。
没有发明新信号，只去掉了重复计数。

### 2.3 为什么本批**不动** `directionFactor`

§6.9 的 α 组合式里**没有** `directionFactor`。照抄意味着负向学习的因子从 0.4 变成 1 —— **负向学习快 2.5 倍**。
文档对此有明确警告："**不要顺便把所有负向学习增强 2.5–4 倍而不评估**"，
并且 §6.9 还要求"**一次只改变一个政策因素**"。

本批同时改了门控（会让学习**变少**），再把负向学习放大 2.5 倍，两个方向相反的力量叠在一起，
**任何结果都无法归因**。所以 `directionFactor` 保持现状，作为**下一个独立候选**单独测量。

### 2.4 为什么 K 次确认缓冲留给下一批

§6.9 的"K 次连续独立合格负残差确认"需要**跨 assessment 的确认缓冲** ——
它是本方案第一个**有状态**改动，要动 `replayModel` 的状态形状与 `MODEL_CHECKPOINT_VERSION`。
不 bump 检查点版本的话，旧 checkpoint 会被恢复到新形状的状态里 —— 正是文档 §14.6 点名要防的复用。
本批先不碰有状态部分。

## 3. §6.7 六种输入情形逐行核对

| 文档情形 | 实现 | 测试 |
|---|---|---|
| 三因子均有效、模型未校准 | E 按公式算；`modelConfidence`/`overall` 均 null；`overallStatus=not_calibrated` | ✅ `the three rule factors combine geometrically` |
| 任一必需因子**缺失** | 不重归一，`evidenceReliability=null`、`overallStatus=insufficient_evidence` | ✅ `a missing factor is insufficient evidence` |
| 任一必需因子**确为 0** | 显式零分支；`evidenceStatus=available`（观测到零）、`overallStatus=insufficient_evidence` | ✅ `a factor of exactly zero is an observed zero` |
| NaN / Infinity / 超 [0,1] | **抛错**，不用 clamp 或默认值掩盖 | ✅ `broken inputs throw` |
| 校准报告但超出适用域 | `out_of_domain` 分支保留（尚无 artifact，未触发） | 未触发（无 artifact） |
| 与校准 artifact 合同相符 | 同上 | 未触发（无 artifact） |

另外：权重必须为正且和为 1，否则抛错（测试覆盖 0 权重与和不等于 1 两种）。

### 3.1 一条必须说清的边界：显式零分支**不可观测**

文档要求"E=0，**显式零分支**，不算 `log(0)`"。我实现了这个分支并写了注释 ——
但**必须承认**：去掉它结果也一样（`exp(0.6·log 0)` 同样是 0）。所以
**这条分支的"存在"无法被测试证明**，测试能钉住的只有它带来的可观测差异 ——
即 `evidenceStatus` 在"零"与"缺失"两种情况下**必须不同**（`available` vs `insufficient_evidence`）。
我没有为它编造一个突变证据。
