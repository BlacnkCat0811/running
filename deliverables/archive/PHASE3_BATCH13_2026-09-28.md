## 2. 关键设计选择

### 2.1 "没有第二个 total" 做成**结构约束**，不是注释

§9.2 的禁令如果只写在注释里，下一次"顺手加个总分"就会绕过它。本版把**字段集合冻结成断言的字面量**：

```ts
assert.deepEqual(Object.keys(vector).sort(), ["activeDurationMinutes", "compositeLoad", ...]);
```

加任何新字段都必须同时改这条断言 —— 那一刻人会读到注释，而不是静默通过。

### 2.2 `activeDurationMinutes` 是**时间**，并有一条断言防止它退化成"另一种 TRIMP"

§9.2 特意点名这一点。断言除了验证 `= durationSeconds / 60`，还验证
`activeDurationMinutes !== 60 * trimpMinuteLoad(1)` —— 把"它是一次 TRIMP"这种误解钉死。

### 2.3 覆盖不足时**宁可为 `null`**，不外推

`highIntensityMinutes` 要求心率覆盖 ≥ `HIGH_INTENSITY_MINIMUM_HEART_RATE_COVERAGE`（0.5），
否则给 `null` + 原因码 `heart_rate_coverage_below_threshold`。
§9.6 明写："partial HR coverage **不能复制整段时长使负荷翻倍**"。

`reasonCodes` 是 §9.2 正文要求（"要注明分区体系和可用覆盖"）的落点 —— 文档给的接口里没有这个字段，
但它的正文要求必须先能表达出来，所以加了这一个字段而不是把信息塞进 `source`。

### 2.4 高档区间集合为什么放在契约层

HR 与 Pace 两套分区**不同构**（`aerobic_power` 只在 HR 一侧存在）。这个集合此前是内联字面量，
再加一份就是两处会静默分叉。放契约层后 `training-load` 只依赖 `@rai/contracts`，
不引入新包依赖，也就不会出现"为了共用常量而依赖 `training-zones`"的环。

## 4. 🔴 顺带确认了 §10.4 的缺陷本体（下一批处理）

§10.4 写的是：

> 注意 HR zone 和 Pace zone 的类别并不完全同构，**不能把各自数组下标相减当"冲突分"**。

`analyzeWorkoutZones` 里 `conflict` 的判定正是这句禁止的写法：

```ts
const conflict = heartCoverage >= 0.5 && paceCoverage >= 0.5 && conflictFraction > 0.3
  && Math.abs(dominantHeart.index - dominantPace.index) >= 2;
```

两套阶梯的实际错位（读源码确认）：

| idx | HR（5 档） | Pace（5 档） | 语义是否对齐 |
|---|---|---|---|
| 0 | `recovery` | `easy` | ≈ |
| 1 | `aerobic_base` | `marathon` | ✗ |
| 2 | `aerobic_power` | `lactate_threshold` | ✗ |
| 3 | `lactate_threshold` | `anaerobic_endurance` | ✗ |
| 4 | `anaerobic` | `sprint` | ✗ |

**从第 1 档起就整体错位**：HR 的 `lactate_threshold`（idx 3）与 Pace 的 `lactate_threshold`（idx 2）
语义**完全相同却下标差 1**；而阈值 `≥2` 恰好把这个错误掩住了 ——
**这条规则目前"看起来对"是运气，不是设计。**

它同时喂 `stimulusConfidence`（`conflict` 时 −0.2）与 `explanationCodes`，
所以修它**会改变对外数值** ⇒ 必须走"先迁移、再离线比较"的路径（§9.5 第 5 条），
**不在本批夹带**。下一批做：显式语义映射 + 真实配对覆盖率（`pairedCoverage` 不能拿
`min(覆盖率)` 冒充）+ 在有/无冲突上的前后对照。
