## 1. 逐条核验（证据到行）

### ① 训练用的是"当天开始前已生效"的 profile

`recompute-pipeline.ts`：

```ts
const localDate = localDateAt(feature.workoutStartAt, request.timezoneIdentifier);
const zoneProfile = zoneProfiles.get(localDate);      // :1275-1276
```

而该日的 profile 在 `:1207` 构造时 `effectiveAt = localDateStartAt(date)`（**当日零点**）。
⇒ `effectiveAt ≤ workoutStartAt` **由算术保证**（当日零点 ≤ 当日任意时刻）。
**除非**训练恰好在零点开始（那时二者相等）—— 那种情况下 ② 的窗口仍然把它排除，所以仍然安全。

### ② 新阈值证据只影响之后的 profile —— **这是唯一的缺口**

profile 自身的输入确实按窗口过滤（`:1196`）：

```ts
thresholdEvidence.filter((item) => item.observedAt < effectiveAt)
```

但 `buildDailyZoneProfile` **自己不校验**：命中 `threshold === null` 分支时**无条件采纳**候选，
不管候选的 `dataThroughAt` 落在哪。换句话说，§10.5 的这条要求**只活在调用方的纪律里**，
换一个调用方就会静默失效 —— 正是"用本次训练推高 threshold，再用新 threshold 评估本次 pace load"。

**已补**（`training-zones/src/index.ts`）：

```ts
if (candidate.dataThroughAt !== null && Date.parse(candidate.dataThroughAt) >= Date.parse(input.effectiveAt)) {
  throw new Error(`threshold pace evidence (...) is not before the profile effective moment (...)`);
}
```

**只拒绝能证明错了的**：`dataThroughAt` 非空且 ≥ `effectiveAt` ⇒ 抛错。
`dataThroughAt === null`（无据可查）**保持允许**，因为现有 `hasNewEvidence` 明确支持
"仅靠 `evidenceCount` 增长"的路径；把它一并拒掉会破坏一条有意的功能。
**这一条残留我如实记下，没有假装已经解决**（见 §4）。

### ③ 被拒绝的候选不会被"衰减后重试"

`training-zones/src/index.ts:279-283` 已有实现，且带注释：

```ts
} else if (hasNewEvidence) {
  // dataThroughAt is the evaluated-evidence cursor. Advancing it prevents a
  // rejected candidate from becoming eligible later only because confidence decayed.
  thresholdDataThroughAt = latestTimestamp(thresholdDataThroughAt, candidate.dataThroughAt);
}
```

**已有测试**：`:285` "does not adopt previously rejected threshold evidence after confidence decay" ✅

### ④ 手工 → 自动的显式切换

`training-zones/src/index.ts:246-251`：

```ts
const switchedPaceToAutomatic = previous?.paceSource === "manual" && settings?.lactateThresholdPace.mode !== "manual";
let threshold = switchedPaceToAutomatic ? null : previous?.lactateThresholdPaceSecondsPerKm ?? null;
let paceConfidence = switchedPaceToAutomatic ? 0 : previous ? previous.paceConfidence * Math.pow(0.5, 1 / 180) : 0;
```

**已有测试**：`:149` "replaces a manual pace anchor immediately after switching to automatic" ✅

## 3. 验收证据

### 3.1 两条新断言

1. **阈值窗口**：`dataThroughAt` 恰好等于 `effectiveAt` ⇒ 抛错；晚 1 小时 ⇒ 抛错；
   早 1 秒 ⇒ 正常采纳（并断言值被采纳）。**三种情形都断言**，避免"只测了拒绝、没测不该拒绝的也被拒"。
2. **RHR / 最大心率窗口**：8 天窗口前读数 50bpm ⇒ profile 取 50；
   一条 70bpm 读数放在 `effectiveAt` 或之后 ⇒ profile **逐位不变**；
   一个 220bpm 峰值放在 `effectiveAt` ⇒ **不被采纳**（窗口取 180）。
   ⇒ 证明这两条输入的时间窗是 **builder 自己**把关的（不依赖调用方）。
   ⚠️ 第一版我断言 50bpm 时得到 60 —— 因为 RHR 候选需要 **≥7 个有效日**才会成立，否则回落默认 60。
   **我的断言前提错了，不是代码错了**（本批第二次）。
