## 2. 关键设计选择

### 2.1 为什么 `assessRecovery` 是**别名**而非保留独立常量

最省事的做法是让 `mobile-coach.ts` 继续持有 `0.75 / 0.85 / 1.03 / 3`，让新包也持有同一组 —— 但那就等于把 §7.1 要消除的"四路独立恢复口径"变成"五路"。所以 `RECOVERY_*` 全部指向
`READINESS_*`，并用一条断言锁死这个关系（`the exported recovery thresholds are aliases, not second copies`）：
**谁把别名改回字面量，测试立刻红**。外部导入者（含既有测试）不受影响。

### 2.2 为什么等价性用**冻结 oracle** 而不是"跑一遍看结果差不多"

重写后的代码自己和自己比，永远相等。所以测试里**原样抄了一份重构前的实现**，且**故意硬编码
`0.75 / 0.85 / 1.03 / 3` 而不 import 新常量** —— 一旦 import，两侧就会随同一处改动一起漂移，测试退化为同义反复。
矩阵取在**每个阈值的两侧**（睡眠 `0.75×430=322.5`、HRV `0.85×52=44.2`、RHR `1.03×53=54.59`），
覆盖 `null` 读数、`stale`/`unknown` 证据状态、以及 0/2/3 的连续坏夜计数。

### 2.3 为什么 `sleepStreak` 要显式出现在输出里

`RecoveryAssessment.sleepStreak` 是既有对外字段。如果 wrapper 自己用 `nightsBelowSleepBaseline >= 3`
重算，阈值就又出现了第二份。因此把它作为 readiness 结果的一等字段暴露，
注释里写明"阈值住在规则里，wrapper 不许再推一遍"。

### 2.4 `state` 与 `assessment` 为什么分开

§7.4 的 `no_low_signal ≠ ready`：只有单项数据、且没看到低信号，**不等于**完全恢复。
按此保留 `coverage=partial / assessment=no_low_signal` 的组合，并用一条断言把它钉死。

## 4. 测试逼出来的一条既有语义（值得记住）

写断言时我以为"RHR 单独升高 ⇒ `low_signal`"，实测**不是**：现有规则里 `low_signal` 要求
**睡眠低**，或 **HRV 低 ∧ RHR 升高** —— RHR 单独升高只在自身信号上记为 `low=true`，
**不改变裁决档位**。

我没有"顺手修好"它，而是**把这个行为写成断言钉住**：
一旦有人改了这条规则，移动的就不只是新包，而是所有既有训练安排。这正是"等价重构"该做的事。
