## 三、判定「不改」的项（附证据，非偷懒）

| 建议 | 判定 | 依据 |
|---|---|---|
| Web `useRemote` 加内存缓存 | ❌ 与设计冲突 | 有测试专门锁"切查询不得显示旧数据"：`hooks.test.tsx` `does not show a cached workout preview while a different path is loading` |
| Web `WorkoutTable` 双 DOM 全量渲染 | ❌ 属冻结区 | `AGENTS.md`：`.workout-mobile-list` **behavior** 未经授权不得改；且窄屏下桌面表格 `display:none`（`styles.css:1144`） |
| Web 图表应读主题变量换肤 | ❌ **臆测** | 全仓 grep：web **不存在** `technology`/`data-theme`/`getComputedStyle`，没有第二套皮肤机制 |
| Web 移动列表对读屏重复暴露数据 | ❌ **不成立** | 窄屏 `.workout-table{display:none}`、桌面 `.workout-mobile-list{display:none}`，`display:none` 本就不进无障碍树 |
| `test:e2e:responsive` 与 `test:e2e:web` 冗余 | ❌ **不成立** | 两者跑**同一文件的不同子集**（`desktopTest`/`responsiveTest` 靠 `npm_lifecycle_event` 互斥 skip），删掉即丢响应式覆盖 |
| worker 重试上限 1s 是"重试风暴" | ❌ **不成立** | 失败重试被 `consecutiveFailures < 3` 限死（`worker.ts:130`），第 3 次起转 `failOutstandingJobs`；1s 只作用于 ≤3 次退避 |
| `/v1/health` 恒 200，应恢复态返 503 | ❌ 会引入回归 | Web 依赖 `200 + databaseReady:false` 渲染首次导入引导（`App.tsx:266-267`）；改 503 会变成 ErrorBlock |
| `saveGoals` 后 `refreshAll` 重复拉 goals | ❌ 必要 | 改周目标需连带刷新本周课表与今日处方，多一次 GET 成本可忽略 |
| `loadCachedData` 加硬 TTL | ❌ 与设计冲突 | 陈旧数据不隐藏，由 `FreshnessBanner` 显式告知（`TechViews.swift:48`、`NativeViews.swift:148`） |
| `localDateTimeAt` "±16h 每 15 分钟暴力解 DST" | ❌ **不成立** | 实现是 **二分查找**（`utils.ts:59-66`），非暴力步进 |
| `normalizeRelativePath` 处的双重小写 | ✅ 已改 | 见 §二.5 |

   报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`。用"把 dist 移走而非删除"绕过后构建正常（EXIT=0）。
   **这是沙箱限制，不影响 CI/服务器。**
3. **vitest 超时问题未复现**：改配置前连跑 4 次（12 文件 / 78 tests）**全部通过**。
   仍加了 `maxWorkers: 2` 作防御，但请勿当作"已修的 bug"——**根因未证实**。
4. **`deploy/upgrade.sh` 未在服务器实跑**：只做了 `bash -n` 语法校验与 `--help` 冒烟。
   首次使用请先跑 dry-run 核对命令序列。
5. **iOS 仅类型级 + 模型级验证**：本机无 CocoaPods，跑不了完整 target 编译；
   视觉层（皮肤分流后的实际观感）无截图基线可比对。
